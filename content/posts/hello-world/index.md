这是本站发出的第一篇，原来兼作使用说明。使用部分已经搬去《[网站使用说明](/blog/core-idea)》，写作与发布见《[本博客的写作与上传](/blog/writing-and-uploading)》。这里只留理念，外加一份项目结构的速写——这台相机由哪些零件组成、四条边界画在哪、每道门禁拦什么；顺便留着当 Markdown 写法的样板。

## 概念：写作即一次长曝光

北半球的一夜长曝光是这样的：相机架在三脚架上，快门长开，恒星绕着天极缓慢走过，底片上留下一条条同心弧——时间本身被写下来的样子。写作在我眼里是同一件事，所以首页就是这台相机：数百条弧绕一枚天极**刚体旋转**累积，基础角速度 `OMEGA = 0.042 rad/s` 全场一致，恒星周日视运动是统一的那一层时间流速。文章不挂在星星上，入口在折线以下的抽屉里。

## 五条原则

出自 `docs/design.md` §2，所有后续决策都要遵守：

1. **冷暖分工，严格不混用**。`--cold` 只给交互（链接、悬停、焦点、星轨节点），`--hot` 只给状态（当前播放、错误、破坏性动作），`--white` 只留给星核与 2px 以内的高光。
2. **主题是叙事，不是皮肤**。切换主题 = 一次夜拍（深色，星轨以 `lighter` 加色发光）或一次显影（浅色，墨以 `source-over` 压在干版上）。任何新增样式必须在两套主题各看一遍。
3. **深度 = 时间**。滚动把 `--shift`（0..1）写进 `<html>`，驱动晕影收紧、首页标题字距拉长与文章页顶部那条进度线。凡"随滚动变化"的视觉都挂这一个值，不允许各自再写一套滚动监听。
4. **文案唯一来源是 `src/data/narrative.js`**。界面只说人话——按钮、眉标、提示、空态一律直陈其物；隐喻只留在两处文学位（首屏十六字与关于页自述）。
5. **可降级**。一切动效都要有 `prefers-reduced-motion` 下的静态出口——星轨会在一次快进里冲成静态底片。站点没有运行时取数：内容在构建期就位，页面加载后不再发请求。

## 项目结构：四条边界

这台相机没有服务端，所以"架构"不是一张分层图，而是四条不许被跨过的边界。跨过去通常不会报错，只会在某个读者那里悄悄分叉：

| 边界 | 由谁钉住 | 跨过去会怎样 |
| --- | --- | --- |
| 内容与界面 | 一卷一目录，`src/data/index.js` 一道门 | 改了不生效，两处说法不一样 |
| 浏览器与 Node | `src/lib/schema.js` 一份字段口径 | 页面与 RSS 各解析一遍，迟早各说一套 |
| 状态与组件 | `src/lib/` 的单例与 store | 换页重铺底片，转场里冻在半帧 |
| 文档与代码 | 四道门禁与测试 | 文档一直讲着一个已经删掉的功能 |

一眼看过去，仓库是这样摆的：

```text
content/posts/<slug>/   一卷文章：index.md + 这张稿子的图
src/
  views/                10 条真实路由与一份 404，视图全部懒加载
  components/           顶栏、首屏、星轨、抽屉卡、搜索、设置、播放器
  lib/                  机制层：底片、取数、字段口径、主题、出口
  data/                 站点内容的一道门：合集 / 动态 / 项目 / 音乐 / 友链
  styles/site.css       令牌与组件契约，全站唯一一张表
scripts/                构建与门禁：SEO、发文校验、命名、对比度、素材烘焙
docs/                   design.md / manual.md：可执行的现状说明
tests/                  Node 内置 runner，零测试框架
public/                 直接上线的静态文件
```

### 内容与界面：一卷一目录

`content/posts/<slug>/` 是文章的最小单位，目录名同时是 slug 与网址。`index.md` 是稿子，同目录其余文件是它的素材：封面按文件名认，常规是 `cover.jpg`，由同目录的 `*-src.jpg` 烘出来；列表页那格、正文顶部那张、映像柜墙上那张读的是同一个文件，作者不在 frontmatter 里写路径，也不在正文里手抄一遍。改名的办法不是维护重定向表，而是在 frontmatter 里写 `movedFrom: 旧名`——构建期把"旧名 → 现名"算成一张小表交给路由，旧链接在组件挂载前就改道。草稿只在 `npm run dev` 里出现：列表、RSS、sitemap、静态壳都不带它。

界面不直接 import 内容文件。`src/data/index.js` 是一道门，加一类内容 = 放一份文件 + 在门上挂一行。唯一直连的是文案层 `narrative.js`，因为它不参与"改一处全站跟着变"，包一层只会让每句话多一次拷贝。文章是另一种例外：它是文件不是数据，取数在 `src/lib/posts.js`。内容取数在运行时是零请求——正文、封面、合集、动态都在构建期就位。

### 浏览器与 Node：同一份 schema

`src/lib/schema.js` 不许出现 `vue`、`import.meta`、`node:fs`，因为它同时被三处 import：页面渲染、构建脚本（sitemap / RSS / 静态壳）、发文门禁。frontmatter 怎么解析、日期怎么判"真是那一天"、封面怎么从目录派生、草稿怎么过滤，只有这一份实现。

这条边界是被一次事故钉住的：过去 RSS 与页面各抄了一遍解析，结果 tags 从来没进过 RSS；缺标题时，一边给空串、一边给 slug。两处代码都能跑，只有对比着读才发现不是同一篇文章。收成一份之后，"页面上看到的"和"RSS 里写的"结构上不可能分叉。`src/data/index.js` 是同一条理由的另一半：它不 import Vue，Node 那一岸 import 得动，于是构建脚本与浏览器读的是同一个对象，而不是两份清单。

### 状态与组件：lib 装会漂移的东西

`src/lib/` 里主要是三种东西：纯模块（`schema` / `feed` / `collections` / `markdown`）、Vue 响应式 store（`theme` / `plate` / `music`）、以及 `sky.js` 这种每帧读写的画布单例——它故意不进响应式，交给 Vue 等于每帧一次重渲染。组件只负责取景与排版，不自己持有跨页的状态；需要跨路由延续的，放进 lib 的单例。

最重的是 `sky.js`：底片像素、星群、天极、时钟、取景权都放在模块级，`StarTrails.vue` 只是架在上面的相机。换页不重铺底片，你翻过的每一页都算进这一夜的曝光；取景权只锁沉积、不锁重绘，否则转场里离开的那台会冻在半帧上；换底片前还会把旧的像素按相似变换搬过去，免得把已感光的弧压成椭圆。这些规则写在库的注释里，因为它们被"顺手优化"时不会报错，只会让某一台设备上的画面错。

### 构建期：一条路径，四道闸

作者每次都会经过的只有三条命令：`npm run dev` 看稿，`npm run build` 出产物，`npm run check` 过门禁。

构建不是单纯打包。`postRolls()` 在启动与构建时读盘，打一份发文回执（卷数、字数、合集、封面、标签、草稿、旧名），frontmatter 键拼错、日期不是真的那一天、合集挂错、有封面却没写 `alt`、两卷认领同一个旧名——任何一条都让构建直接红，不出产物。`build_seo.mjs` 在同一份清单上写 sitemap、RSS（全文）和每条真实路由的静态壳：GitHub Pages 不回退未知路径，深链能打开靠的就是这些构建期写好的 HTML。

`npm run check` 是四道互不重叠的门：内容、文档引用、命名、主题令牌对比度。`tests/` 用 Node 内置 runner，常见约定各有对应的测试——CRLF 检出、旧链接改道、两张详情页不许各抄一份跳转、声波只许长在折线以上，都能找到那枚钉子。门禁长在构建里而不是只长在测试里，理由很实际：测试可以被跳过，构建是每次上线都必经的那条路。过去 CI 只有 `npm ci` 与 `npm run build`，没有任何一条检查读过 `content/posts/`，于是正文引用的图没进产物、日期写歪、键名拼错，全是"构建绿、线上 404 或空块"。

### 这套结构的代价

四条边界买来的是"一件事只有一个实现"，代价是每一处都得自己守。

- 静态壳是 SPA 深链的补丁，不是什么新办法。Pages 的回退规则不改，它就得在构建期存在。
- `site.css` 是一张单表，令牌与组件契约都在一起；它自有一套小节编号，文档按编号引用，改一处时仍要整表读。
- `HomeView` 与 `StarTrails` 是大文件，常数写在渲染循环旁边。拆开会让"这个数为什么是这个数"离使用处更远，所以没有拆。
- 文档能当契约，但门禁有盲区：`check:docs` 只扫四份文档（README 中英、design、manual），代码注释里的 `§` 引用不在扫描范围；带字母的锚（`§6c`）会被正则截成 `§6`。文档在描述一个已删功能，几道门禁都核不出来。
- 不少测试读的是源码文本，钉的是约定而不是行为。它们能拦住"改回去"，不证明运行时正确。

结构不是把文件分成几层，而是把会分叉的判断收成一处，把必须在构建期知道的事挪到构建期，剩下的交给一张不重铺的底片。

## 可读性：一层底板，一类表面

次级页背后是一层固定的风景底片：照片从页顶一直露到页面下方，越往下越暗，到页面下方落成 `--ink-0`。文字不直接坐在照片上——页头坐在一张卡面上，顶栏没有垫任何色面，字色按当前那张底片顶带的亮度在墨字 / 纸字之间换；卡面默认不透底，文章页与项目详情页共用一块 `.en-glass` 阅读底板；设置卡可以把卡面切到半透（52%），那时边界只剩 `--card-brd` 那根发丝线。三件事各归各的令牌：**压暗渐变管"读得清"，卡面管"是一组"，阅读底板管"长时间阅读时的隔离"**。

## 一张卡面，一组刻度

`.en-card` 是全站唯一的卡片表面——边、角、底、hover、内边距、210px 最小高全部取自 `--card-*`。栅格可以不同（`.en-cards` 两列、`/blog` 三列、首页精选三格），卡面不许另造。尺寸全部走刻度：间距 `--space-0…5`、字号 `--fs-3xs…4xl`（最小一档 11.5px，仪器文字再小就不可读）、行高 4 档、字重 3 档。组件内不写裸字号、不写裸间距。

## 底片不重铺的代价

底片跨路由常驻，最贵的一处不在代码，在像素：它按视口尺寸分配，`MAXPX = 9e6` 封顶，超了就自动降 DPR，下限 `MIN_DPR = 1.8`。这个下限想治的"采样网格起伏"其实治不了——1× 屏眼睛采样的是 1 CSS px，把底片栅格加密并不动它；留下它只为同心弧的台阶更细，而这一条没有量过。代价是 1× 大屏每帧全屏 `destination-out` + `drawImage` 多 2.7 倍像素，要不要退回 `devicePixelRatio` 还得看实际帧率。
