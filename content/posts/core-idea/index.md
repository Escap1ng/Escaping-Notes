这一篇讲**怎么用它**，面向读者。作者侧的写作与部署流程在 `docs/manual.md`（§2 编辑、§4 上线），写作为什么这样设计见《[设计理念](/blog/hello-world)》。全站界面文案大多收在 `src/data/narrative.js`，设置卡与搜索卡里的局部提示随组件走；下面引用的措辞以页面为准。

## 导航：六枚编号

顶栏从 `00` 排到 `05`，编号即站点结构，没有二级菜单：

| 编号 | 路由 | 里面是什么 |
| --- | --- | --- |
| `00 首页` | `/` | 长曝光星轨；折线以下是一块抽屉：本地时刻、精选三篇、最近五条动态 |
| `01 文章` | `/blog` | 三列封面卡，带搜索框与标签筛选 |
| `02 动态` | `/updates` | 一句话一条，每条一枚卡 |
| `03 映像` | `/gallery` | 全站用过的图片，摊成一墙 |
| `04 项目` | `/projects` | 做过的东西 |
| `05 关于` | `/about` | 自述、档案、装备、友链 |

视口 ≤1280px 时整条导航收进右上角的汉堡抽屉。这个断点不是估的：一枚导航实测占 67.6px + 4px 间距，当前六枚整条约 425px，多一枚就要把折叠线抬一档。

## 右上的四枚

导航之外，顶栏右侧固定四枚按钮，窄屏时再并出一枚汉堡：

- **搜索**：点开一张卡片，按标题 / 摘要 / 标签即时筛；`Enter` 把词交给 `/blog?q=`，点结果行直接进文章。它和 `/blog` 那一格用同一条判据，站内没有第二套搜索状态。
- **主题**：深色 / 浅色切换，选择存进 `localStorage['en-theme']`，下一程接着用。
- **音乐**：点开播放器卡，有上一首 / 播放暂停 / 下一首 / 进度 / 音量 / 队列；没有曲目时按钮置灰。
- **设置**：底片模糊 0–12px（0 即清晰，只作用于折线以下的风景底片）与卡片颜色两档（默认不透底，另一档半透 52%）。两枚都即时生效并记住。

三张卡（搜索 / 播放器 / 设置）都贴在顶栏下沿，任何时刻只开一张；点卡外或按 `Esc` 收起，焦点回到按钮，`Tab` 锁在卡内。

## 读：列表、筛选状态与正文

`/blog` 的搜索词与选中标签写进 URL（`?q=` / `?tag=`，走 `router.replace`），所以筛选结果**可分享、刷新不丢、前进后退可回放**。「列表本来为空」和「筛选后为空」是两句不同文案（`// 还没有文章` / `// 没有符合条件的结果`），后者不代表站点没内容。

正文单栏，栏宽跟着字号长（`--measure = --prose-size × 44`，一行恒为 44 个汉字）。文章页顶部那张满栏封面由构建期从这一卷的 `cover.jpg` 自动插进正文，正文里不用手写；文中图片点按进看片框。页尾是「← 上一篇 / 下一篇 →」与一枚「返回文章列表」。键盘用户第一次按 `Tab` 落在「跳到内容」上，直接进 `#main`。

## 听：一台引擎，一张卡

播放状态与操作只在 `src/lib/music.js` 一处，全站唯一的 `<audio>` 也在那里；界面只有顶栏那张播放器卡——上一首 / 播放暂停 / 下一首 / 进度 / 音量 / 队列都在卡里。

原 `/records` 音乐页已经下线，站内曲目不再单独成页；选曲、续播与系统媒体键都由右上角那张卡承担。

## 看：映像墙与它的键盘操作

`03 映像` 收的是**站内已经用过的图片**：文章封面由 `content/posts/<名字>/cover.jpg` 自动收（这一卷里有这张图就上墙，不必登记），站点自己的底片（首屏地平线、抽屉轮播那五张、深色压暗底、分享卡）登记在 `src/data/gallery.js`，两路按 `src` 去重。照片按原比例上墙，不做 3:2 裁切——列表页那格封面才选焦点裁一格。点开进看片框：`←` / `→` 翻页，`Esc` 关闭，触屏横滑超过 50px 翻页，`Tab` 被锁在框内。

## 外观、设备与降级

- **双主题**：深色（星轨以 `lighter` 加色发光）与浅色（墨以 `source-over` 压在干版上），右上角切换，选择存进 `localStorage['en-theme']`。默认浅色，首帧刻意不读 `prefers-color-scheme`——首屏是一张亮底照片，跟系统翻到深色会变成亮图压在黑底上。
- **减弱动态效果**：系统开了 `prefers-reduced-motion` 时，星轨降级为一次性快进生成的静态底片，`fall` 转场与晕影关停，折线以下的底片轮播停在第一张。
- **窄屏**：≤1240px 顶栏先收品牌昵称；≤1280px 整条导航收进汉堡抽屉；≤900px 文章列表与映像墙收两列；≤880px 通用卡片栅格收单列；≤720px 页边距收窄，文章列表与映像墙改单列，灯箱箭头让位给横滑，输入框字号 ≥16px（防 iOS 聚焦放大）；≤480px 顶栏只剩圆环图标。
- **触控与字号**：触控设备上的按钮与胶囊 ≥44px，最小字号 11.5px。
- **可读性**：次级页背后是一层固定的风景底片，从页顶的透明羽化渐隐到页面下方的实底；文字落在不透底的卡面或阅读底板上，不直接坐在照片上。设置卡可以切到半透，那时卡片边界只剩一根发丝线。

## 数据：构建期定稿

站内没有服务端，也没有运行时请求：文章是仓库里 `content/posts/<名字>/index.md` 一卷一卷放着，站点内容（动态 / 项目 / 装备 / 音乐 / 映像 / 友链）是 `src/data/*.js`，两者都在构建时打包进产物。GitHub Pages 与 Vercel 看到的是同一份内容：Pages 为每条真实路由预写一份 HTML，深链直接命中；Vercel 用 `vercel.json` 的 rewrite 接住深链。站内只有 history 一种路由模式，旧的 `#/...` 链接会在应用挂载前改道成路径形状，不会静默落在首页。

订阅地址是 `/rss.xml`：`index.html` 里挂了 `<link rel="alternate">`，浏览器会自己识别，页面上没有按钮。要发文或改站点信息，就是改仓库里的文件再 push，细节见 `docs/manual.md` §2 与《[怎么写、怎么发](/blog/writing-and-uploading)》。
