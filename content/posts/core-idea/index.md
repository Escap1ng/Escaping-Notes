这一篇讲**怎么用它**，面向读者。作者侧的写作与部署流程在 `docs/manual.md`（§2 编辑、§4 上线）。界面文案全站只有一个来源（`src/data/narrative.js`），所以下面引用的每一句措辞，与你在页面上看到的是同一句。

## 导航：七枚编号

顶栏从 `00` 排到 `06`，编号即站点结构，没有二级菜单：

| 编号 | 路由 | 里面是什么 |
| --- | --- | --- |
| `00 首页` | `/` | 长曝光星轨；折线以下是一块抽屉：本地时刻、精选三篇、最近五条动态 |
| `01 文章` | `/blog` | 三列封面卡，带搜索框与标签筛选 |
| `02 动态` | `/updates` | 一句话一条，每条一枚卡 |
| `03 音乐` | `/records` | 歌单快照 + 站内自托管 mp3 的曲目表 |
| `04 映像` | `/gallery` | 全站用过的图片，摊成一墙 |
| `05 项目` | `/projects` | 做过的东西 |
| `06 关于` | `/about` | 自述、档案、装备、友链 |

视口 ≤1280px 时整条导航收进右上角的汉堡抽屉。这个断点不是估的：一枚导航实测占 67.6px + 4px 间距，多一枚就要把折叠线抬一档。

## 读：列表、筛选状态与正文

`/blog` 的搜索词与选中标签写进 URL（`?q=` / `?tag=`，走 `router.replace`），所以筛选结果**可分享、刷新不丢、前进后退可回放**。「列表本来为空」和「筛选后为空」是两句不同文案（`// 还没有文章` / `// 没有符合条件的结果`），后者不代表站点没内容。

正文单栏，栏宽跟着字号长（`--measure = --prose-size × 44`，一行恒为 44 个汉字）。文中满栏图点按进看片框；页尾是「← 上一篇 / 下一篇 →」与一枚「返回文章列表」。键盘用户第一次按 `Tab` 落在「跳到内容」上，直接进 `#main`。

## 听：两处入口，一台引擎

播放状态与操作只在 `src/lib/music.js` 一处，全站唯一的 `<audio>` 也在那里；`/records` 的曲目表和顶栏那张播放器卡片读的是同一个 store，所以不会出现两处各播各的。点曲目表任意一行即播；卡片上是进度、音量与队列。

## 看：映像墙与它的键盘操作

`04 映像` 收的是**站内已经用过的图片**：文章封面由 `content/posts/<名字>/cover.jpg` 自动收（这一卷里有这张图就上墙，不必登记），站点自己的底片（首屏地平线、抽屉轮播那五张、深色压暗底、分享卡）登记在 `src/data/gallery.js`，两路按 `src` 去重。照片按原比例上墙，不做 3:2 裁切——列表页那格封面才选焦点裁一格。点开进看片框：`←` / `→` 翻页，`Esc` 关闭，触屏横滑超过 50px 翻页，`Tab` 被锁在框内。

## 外观、设备与降级

- **双主题**：深色（星轨以 `lighter` 加色发光）与浅色（墨以 `source-over` 压在干版上），右上角切换，选择存进 `localStorage['en-theme']`。默认浅色，首帧刻意不读 `prefers-color-scheme`——首屏是一张亮底照片，跟系统翻到深色会变成亮图压在黑底上。
- **减弱动态效果**：系统开了 `prefers-reduced-motion` 时，星轨降级为一次性快进生成的静态底片，`fall` 转场与晕影关停，交互层撤掉。
- **窄屏**：≤900px 文章列表与映像墙收两列；≤880px 通用卡片栅格收单列；≤720px 页边距收窄、输入框字号 ≥16px（防 iOS 聚焦放大）。触控目标统一 ≥44px，最小字号 11.5px。
- **可读性**：文字底下的天空由一条全站统一的暗带压低（系数 `--sky-k` 两套主题各一档），不靠每张卡片各自蒙一层纱。

## 数据：构建期定稿

站内没有服务端，也没有运行时请求：文章是仓库里 `content/posts/<名字>/index.md` 一卷一卷放着，站点内容（动态 / 项目 / 装备 / 歌单 / 映像 / 友链）是 `src/data/*.js`，两者都在构建时打包进产物。GitHub Pages 与 Vercel 上的内容因此完全一致，路由模式也一致（都是 history）——`/blog/<slug>` 这种地址在两边都是直接命中一份构建期写好的 HTML，不靠服务器回退。

订阅地址是 `/rss.xml`：`index.html` 里挂了 `<link rel="alternate">`，浏览器会自己识别，页面上没有按钮。要发文或改站点信息，就是改仓库里的文件再 push，细节见 `docs/manual.md` §2 与「怎么写、怎么发」那一篇。
