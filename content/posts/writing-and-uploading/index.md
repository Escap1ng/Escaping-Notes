这台相机怎么进一卷新底片，说清楚只要三句话：**一篇是一个目录，封面是原图就地烘出来的派生素材，上线是一次 push**。下面把这三句摊开——它同时也是 `docs/manual.md` §2.2 与 §4 那两节的一份读者版。站点为什么这样设计见《[设计理念](/blog/hello-world)》，读者怎么用见《[网站使用说明](/blog/core-idea)》。

## 只有一条路：改仓库里的文件

站内没有后台。文章就是仓库里 `content/posts/<名字>/index.md`，站点内容（动态 / 项目 / 装备 / 歌单 / 映像 / 友链）就是 `src/data/*.js`——改完 push，GitHub Actions 先跑 `npm test` 与 `npm run check`，再构建发布。没有一份内容躺在别处等着同步，也没有"必须在网页上改才生效"的东西。

## 写作：一卷目录就是一篇

**目录名就是网址。** `content/posts/writing-and-uploading/` 落在 `/blog/writing-and-uploading`，所以名字用英文小写短横线，改名字等于换网址。素材和稿子平铺在同一层，一卷带插图时大致长这样（示意）：

```
content/posts/<slug>/
  index.md          ← 稿子，文件名固定
  cover-src.jpg     ← 原图，不进仓库也不上线（.gitignore 里写着 *-src.*）
  cover.jpg         ← 烘出来的封面，上线的就是它
  dune.jpg          ← 正文里的插图，爱几张几张
```

素材文件名要全小写、不带空格：带空格的图片会中断 Markdown 的图片语法，大写字母在 Windows 上不敏感、在 Linux 静态托管上敏感，两边不是同一个名字。

`index.md` 开头两条 `---` 之间是 frontmatter，一行一条 `key: value`：

```markdown
---
title: 文章标题
date: 2026-10-10
tags: [手册, 设计]
summary: 一句话摘要，列表页、RSS 和分享卡都读它。
alt: 暮色里覆雪的富士山压着一带云，山脚铺开一座城
---
```

封面**不在这里写路径**：这一卷里有 `cover.jpg`（也认 `.jpeg` / `.png`），列表页那格、正文顶部那张满栏图、映像柜墙上那枚拍立得、分享卡就都是它，一处也不用提第二遍；同目录出现两张候选封面会被门禁报出来。没有封面也是合法状态，列表那一格留一张等高的斜纹空版——卡片高度不齐比没图更难看。`alt` 有封面就必须写，读屏靠它，图挂了也靠它。还有个可选的 `imagePos`，值是 CSS `background-position` 那套写法（比如 `50% 30%`），管封面在 3:2 的卡格里露哪一块；不写就是 `center`。

上面那五行里 `date` 最容易被忽略，也最要紧：全站按它倒序排——文章列表、首页抽屉那三格精选、映像柜墙上第一格、RSS 里的先后，都是最新那篇在前。漏写会回落到 `1970-01-01`，这篇就永远沉在最后。

另有两个键管的是**发不发布**，不是长什么样。`draft: true` 让这一卷只在本地开发时露面：构建产物里连它那张封面都不拷，RSS、sitemap、分享卡、列表与读数全都不算它，所以写了一半直接 push 也不会被读者先看见；回执会在那一行标【草稿】，不让你以为它发出去了。`movedFrom: [旧slug]` 登记这篇以前用过的网址——目录名就是网址，改名之后旧链接靠这一行跳到现名，而不是落到「这里没有这一篇」。有一条代价要知道：Pages 上旧网址本身没有对应的静态壳，首个请求的状态码仍是 404；应用经 `404.html` 装载后会立刻改道，读者看得到内容。

正文是标准 Markdown，四条本站特有的约定：

- `#` 让给文章标题，正文从 `##` 起，所以实际渲染出来最高到 h6。
- 表格第二行那行分隔符**必须**写，缺了整段会按普通文字排版。列对齐由它上面的冒号决定：`:---` 左、`---:` 右、`:---:` 居中。
- 链接与图片的地址只接受站内相对路径、锚点、`http(s):`、`mailto:`、`tel:`。写成 `javascript:` 之类的不会变成链接，只保留可见文字。原因不是排版而是安全：正文会经 `v-html` 渲染给每一个读者，一条能点就能执行的地址足以在访客的浏览器里跑任意脚本。
- 插图就扔进这一卷的目录里，正文里只写文件名、不写路径：

  ```markdown
  ![沙丘](dune.jpg)
  ```

  构建期把它改成本卷的网址 `/blog/<slug>/dune.jpg`；写错名字或忘了放图会在构建时当场拦下，而不是等读者看见一个破图占位。`alt` 要真的描述画面。封面不用在这里写：构建期会把它自动放在正文最前面，正文里再抄一遍反而会被门禁拦下。

字数与阅读时长不用你写：只统计正文（frontmatter 不计，去掉空白后按字符数算），按 400 字一分钟折算；列表卡、文章页、RSS 与发文回执读的都是同一个数，构建期自动插在最前面的那行封面不计进字数。

## 封面：原图不进仓库

`cover.jpg` 是派生物，不是素材。两步：

1. 原图丢进这一卷的目录，名字以 `-src.jpg` 收尾（`.png`、`.webp`、`.tif` / `.tiff` 都认）。`*-src.*` 在 `.gitignore` 里，不进仓库也不上线。
2. `npm run cover:build`，同目录烘出 `cover.jpg`——长边 1600px、JPEG 质量 72；这一篇的封面烘出来是 155KB。

烘哪些、不烘哪些由目录决定，不再有一张手写的映射表；一卷里出现两张 `*-src.*` 时脚本会停下来，因为它没法替你挑一张。长边 1600 也不是拍脑袋——这张图最宽只会被画到阅读栏，而阅读栏封顶是 `--measure` = 44 × 20px = 880 CSS px，1600 给 2x 屏留了余量。质量 72 高于底片那批，因为底片是垫在文字后面被糊的，这张是读者点开来看的。

列表页那一格和正文顶部这一张是**同一个文件**：一边圆一边方会读出「换了个东西」，所以两处共用同一份派生图，圆角由 CSS 给。

`content/posts/*/cover.jpg` 与 `public/plates/` 这两批派生物**必须进仓库**。原因很实在：烘图脚本跑在 Windows PowerShell + System.Drawing 上，Pages 的 ubuntu runner 执行不了，CI 里也装不了 PIL 或 sharp。仓库里这一份就是唯一的一份。过去给它们加一条忽略规则的后果是静默的——构建不报错，线上每张封面都是 404；现在这条路已经堵住了，构建期会读盘核对（下一节）。

## 上传：push 即上线

发之前跑一遍自检：

```powershell
npm run build       # 先打一份发文回执，再出 dist/（含 rss.xml / sitemap.xml）
npm test            # 内容校验、Markdown 渲染、底片清单与 site.css 对拍、主题口径
npm run check       # 回执 + 文档死链与节号、命名规约、主题令牌对比度
npm run preview     # 本地模拟线上环境，浏览器过一眼
```

CI 的发布路径也会跑 `npm test` 与 `npm run check`，任一条红就不发布。回执长这样，每一卷一行；有问题就不出产物，`npm run dev` 只打印不拦（半篇稿子要能接着写）：

```
发文回执 · 3 卷
  core-idea                    2026-09-01   2637 字 ·  7 分钟  封面 ✓  标签 手册
  ...
```

| 方式 | 落在哪 | 是什么 |
| --- | --- | --- |
| GitHub Pages | `escaping.top`（主线） | `git push` 后 Actions 自动构建并发布。文章与配置都在构建期打包 |
| Vercel | `xxx.vercel.app` | 另一份出口，同样 push 即部署，看到的是一模一样的内容 |

两种方式都是纯静态托管，没有服务端能动态生成东西：`sitemap.xml` 与 `rss.xml` 由构建期的 `scripts/build_seo.mjs` 依 `content/posts/` 生成，随站点一起发布。RSS 带全文与标签，阅读器里不必跳回站点就能读完一篇。

## 发完之后会自动变的四处

不用手工登记的地方有四处：文章列表多一格封面、首页抽屉的精选卡换了一轮（取最新三篇）、映像柜墙上多一枚拍立得（这一卷的封面自动上墙，最新那篇在左上第一格），以及**这一篇自己的那条链接**——构建期为它在 `dist/blog/<slug>/` 写一份真实 HTML，标签页与分享卡上说的那句话、那张图，就是这一卷的 `title`、`summary` 与 `cover.jpg`。GitHub Pages 不会把未知路径回退到站点首页，所以这条链接能被直接打开、状态码是 200，而不是一句 404。

只有站点自己的底片要登记——首屏的地平线、抽屉轮播那五张、深色那张压暗底、分享卡，记在 `src/data/gallery.js`。这份清单与 `site.css` 里真正引用的 `/plates/` 路径由 `npm test` 对拍，两侧必须咬合：换底片只改了 CSS 而忘了这里，映像柜就会把一张全站已经不用的图留在墙上示众。
