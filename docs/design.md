## 1. 核心概念（≤200 字）

首页是一台架在三脚架上的相机在长曝光：数百条星轨弧绕一枚偏心天极刚体旋转累积，恒星周日视运动是全场一致的时间流速（其上叠一层全局 ±22% 的慢呼吸）。文章从折线以下的精选卡进入。色彩取自夜空的两副面孔——深色为冷白/暖白/琥珀，浅色为板岩/石墨/朱砂；色温跟星等走（暗星冷、少数亮星抽暖），冷暖分工不混用；山体在地景横带内沿脊线遮挡星轨。滚动即曝光加深：晕影收紧、天空转快。

访客一句话复述：**"这是一个把博客做成相机长曝光的网站，滚动就是这一夜在加速。"**

## 2. 设计原则（增补：所有后续决策需遵守）

1. **冷暖分工，严格不混用。**
   - `--cold`（冷）只用于**交互**：hover / 链接 / 焦点 / 星轨节点 / 光标 caret / 标签。
   - `--hot`（热）只用于**深度 / 强调**：进度 / 主动作按钮 / 日期 / 当前项 / 朱砂点睛 / 正文 h2 左缘。
   - `--white` 只用于**星核高光 / ≤2px 高光**（光子环、按钮扫光），不铺大面积。
2. **主题是叙事，不是皮肤。** 切换主题 = 一次"夜拍"（深色）或一次"显影"（浅色），由 `theme.js` 驱动 `data-theme`。任何新增样式必须在两套主题各看一遍（深色/浅色）。
3. **深度 = 时间。** 滚动把 `--shift`（0..1）写入 `<html>`，驱动晕影加深、首页标题字距被潮汐拉长、星轨提速。凡涉及"随滚动变化"的视觉，都应挂在 `--shift` 上，而不是各自写死。
4. **文案唯一来源是 `narrative.js`。** 视图里不要出现硬编码的界面文案（尤其对偶联、按钮、眉标、空态）。
5. **可降级。** 一切动效都必须有 `prefers-reduced-motion` 降级；API 不可达时站点仍是完整离线底片。

## 3. 两个核心装置与一条位置协议

### 3.1 长曝光星轨（`components/neo/StarTrails.vue`）

- **概念**：首屏 = 架在三脚架上的相机长曝光。恒星周日视运动是刚体旋转（全场一致 ω≈0.042 rad/s），星轨绕偏心天极（全站同一处：视口 50%x / 38%y；首屏改居中排版后环心回到水平正中）累积成同心弧。**但刚体旋转只保证几何正确，不保证好看**：可读的星空靠的是星等分层（多数暗、极少数亮）与弧长错落，见下「星等与随机性」。恒定 ω 之上另叠两个不可通约慢波的 ±22% 呼吸（`GUST_*`）破节拍器感：全场仍共享同一 ω，不做差速（2026-10-09 第七轮）。
- **渲染管线（Canvas 2D · 累积缓冲）**：ACC 离屏底片按**视口**尺寸分配、全站共享（见下「天与相机」），每帧不清空——① 衰减 pass：`destination-out` 填 `alpha=fade`（尾迹长度 ∝ 1/fade）；② 增量 pass：每星画本帧短弧沉积，**弧长由 `shear`（0.06~0.40rad 随机）主导，而不是 ω·dt（每帧仅 0.0007rad）**——这一条最容易记错：调 ω 改的是天空转动的快慢，改弧长要动 `shear`。`z>0.62` 的亮星（实测占 14.2%）另在拖痕前沿叠一笔 22% 长、0.72 倍线宽、`HEAD_GAIN=2.6` 倍 alpha 的短弧，使亮度自尾向头递增（实测累积比 1.3~1.6 倍）——等亮的长弧在视觉上只是"一根光棒"。主画布每帧 = 底 → `drawImage(ACC, 0, 0, W, H)`（顺带把天区坐标缩放进本机盒子）→ 当帧层（流星，不累积，保持锐利）→ 首页相机末尾 `destination-in` 山脊遮罩（见第七轮）。底片内部分辨率 `dpr = min(2, max(1.8, devicePixelRatio), √(9e6/(w·h)))`——**1.8 是下限**（2026-10-07 加，见「细线串珠」），9MP 是预算封顶，相机跟随底片 DPR。
- **天与相机（`src/lib/sky.js`）**：底片像素、星群、天极、时钟、取景权放在模块级单例 `sky` 里——**星空是一份，相机是两台**。要点：
  - `ensurePlate()` 只在**视口尺寸或 DPR 变化时**才新建底片；桌面换页时两者都不变，于是同一张底片继续感光。这是"一夜连续曝光"从口号变成实现的唯一一处改动。**但移动端会变**：地址栏收放改 `innerHeight` → `resize` → 走到重开分支，早期版本等于用户第一次滚动就把整夜曝光倒掉（且只在手机上发生，桌面测不出）。现在重开前把旧底片搬进新底片，**但必须是相似变换**（绕旧极点等比缩放 `s = 新maxR/旧maxR`，再把旧极点平移到新极点），不能按 x/y 两轴各拉伸一次——两轴拉伸会把已经感光的弧压成**椭圆**：滚动条一出现 `innerWidth` 少 ~17px，在 r=1601 的弧上圆度误差就有 10.6px（肉眼直接读出"不是正圆"），手机地址栏收放那种 100px 的高度变化误差 61px，桌面从 1920×1080 拉到 2557×1300 是 157px。相似变换的圆度误差恒为 0；极点按新尺寸重算带来的那一两度漂移仍在，**漂移可接受，黑屏和椭圆不可接受**。
  - `sky.t0` 全站起一次，星角 `s.th` 因此跨路由连续；组件卸载只 `releasePlate(self)` 交还取景权，**不再把 `acc` 置 null**（那正是过去每次导航重铺底片的根因）。
  - **取景权**：`fall` 是并行转场，离开方与进入方并存约 260ms（leave 0.26s / enter 0.44s），两台相机同时往一张底片沉积会画双份、`resize()` 还会互相清屏。故底片同一时刻只认一个主人，后挂载者接管。**但取景权只管沉积，不管重绘**：`ownsPlate()` 只包住 `update()` 里的 `accPass()` 与抽独立尾部那一段，非主人照样每帧 `draw()`。早期版本把它写进了 `tick()` 的停帧条件，结果交出底片那台在淡出的 260ms 里**冻在半帧上**——那就是切换顿挫感的来源。
  - **坐标**：星群/指针都在天区坐标，指针经 `toSky()` 换算回天区（`kx/ky` 那一路换算随变星装置一起撤除，2026-10-09 第八轮）。**两台相机的盒子一律取视口**（`resize()` 里不再量 hero 的盒子），所以天区与相机恒为 1:1，不是巧合：首页 `.hero` 是 `100svh`，手机上比 `innerHeight` 小最多 ~17%，拿它当相机会把底片**非等比压扁**——同心弧在首页变椭圆、进文章页又跳回正圆，正是统一天极要消灭的那种穿帮。多出来的一截由 `.hero{overflow:hidden}` 裁掉，牺牲几十像素取景，换几何不出错。
  - 天极**全站统一**为视口 `0.5 / 0.38`（原先次级页是 0.5/0.4，更早全站是 0.62/0.38——偏右上是给当年贴左下的宣言让位，首屏居中排版后环心回到水平正中）。两台相机极点不同，导航后同心弧的圆心会跳，"同一片天"当场穿帮。
- **Props / Emits（开发用）**：

  | 名称 | 类型 | 默认 | 说明 |
  | --- | --- | --- | --- |
  | `interactive` | Boolean | `false` | `true` 才启用流星/指针层及 `--lx/--ly` 时间膨胀；`false` 无交互层、限帧 30fps，只作活背景。**星数与之无关**——星群属于全站共享的天空（按视口宽度与主题定数，深色再乘 `N_DEEP_K`），次级页若少沉积一半星，那些圆弧会在阅读中因全局衰减慢慢消失 |

- **交互语义**：滚动 = 时间流速（`flow = 1 + k·2.2`，`fade` 由 0.172→0.104；尾迹长度按 `(flow·FADE_0/fade)^0.28` 放大弧长（`LEN_POW`），所以越深天越快、弧也越长）；指针 = 引力时间膨胀（180px 半径内转速×2.8、提亮，轨迹局部卷曲，移开恢复）。**为什么长度挂在弧上而不是衰减窗口上**：8 位底片的衰减窗口最长只能到 ~1.4s，再长就把扫过的一整圈焊死在底片上。
- **主题**：色温跟星等走（见 2026-10-09 第七轮）：深色 = 冷白（暗）/暖白（中）/琥珀（亮星点睛），`lighter` 发光；浅色 = 板岩（暗）/石墨（中）/朱砂（亮星点睛），`source-over`，fade×1.4 尾迹更干净。**浓淡常量分主题，不共用一个数**：沉积浅色 ×1.5、深色 ×1；衰减浅色 ×1.4、深色 ×1；**星数深色 ×`N_DEEP_K`(0.65)**——近黑底会把每条线的抗锯齿翼放大成一片脏灰。**换主题才"换一张底片"**（防串色），并且**要连带重播星群**（星数变了）：`readColors()` 拿 `data-theme` 与 `sky.theme` 比对，相同就直接返回——两台相机各挂一个 MutationObserver，一次切换会进来两趟，靠这个比较幂等。**挂载不重铺**。换主题同时重建山脊遮罩（两个主题的地景是两张不同的照片）。
- **部署**：首页由 `HorizonHero` 以 `interactive` 挂载；次级页由 `App.vue` 以非交互模式挂载为活背景；两者看同一张底片（§3.1「天与相机」）。`reduced-motion` = 一次性快进 380 步生成静态底片，不启动 rAF；由 `ensureStaticPlate()` 按 `sky.plateBuilt` 保证**每张底片只冲一次**，换页与第二台相机都不重冲。
- **次级页限帧（1.2.0）**：非交互模式目标帧率 30fps（`SUB_FPS`），不足一帧间隔时 rAF 回调直接返回、不绘制。`update()` 用的是真实 `dt`（≈33ms），故星轨转速与满帧完全一致，只是全屏 `destination-out` + `drawImage` 的绘制量减半。首页交互层不受影响（满帧）。
- **次级页曝光响应（「阅读即曝光」）**：非交互模式原先只有页顶一个固定基线，整篇文章的星空一样静。现在 `update()` 每帧读 `src/lib/shift.js` 的 `shift.v`（文档级滚动深度，由 `App.vue` 的 `applyShift` 写入），推进 `flowT = 1 + d·SUB_FLOW`（`SUB_FLOW=1.1`，首页 `FLOW_MAX` 的一半，次级页保持克制）与 `fadeT = SUB_FADE_TOP − d·(SUB_FADE_TOP − FADE_1)`（`SUB_FADE_TOP = FADE_0·1.3`）——页顶是安静的短尾迹，越往下读曝光越久、尾迹越长、天空转得越快，目标值交由既有惯性推进平滑，不加额外补间。深度取**文档级**而非首页那套 `scrollY/(H·1.1)`：长文章滚过一屏后者就饱和了，读不出整篇的进度。`reduced-motion` 无需另设分支——`tick()` 在 `reduced` 下直接返回，`update()` 根本不执行，静态 `buildPlate()` 底片即是结果。
- **两道停帧闸门 + 一道沉积闸门**：`tick()` / `kick()` 只看两件事——① `document.hidden`（`visibilitychange`，标签页不可见即停）；② `onScreen`（**仅首页相机**：hero 在流内，整块滚出视口后没人在看，别再白画。用 `IntersectionObserver` + `rootMargin: 200px` 外留余量，回滚时不会先撞上一帧停滞的画面；次级页相机是 `position: fixed` 满屏，恒在视口内，不需要观察）。**取景权不在这两道闸门里**（见上，它只关沉积）。停帧期间星角冻结——等价于镜头被盖上时不再曝光，回到视口后按 `dt ≤ 48ms` 的上限续长，不会跳变。
- **惯性常数 `0.94`**：`flow` / `fade` / 指针光锥都按 `1 - 0.94^step` 向目标推进，约 1 秒收敛。早先是 `0.9`（≈1/3 秒），改滚动速度的瞬间天空会"弹"一下；放缓之后是被慢慢推动的。这一条与 `fall` 同属"整体舒缓"的方向。
- **流星 × 播放**：`update()` 在生成下一颗流星的时刻读 `music.playing`（`src/lib/music.js`）：在响则把随机间隔压向最短值（区间长度 ×0.4），停下后**下一次生成**即自然回弹。刻意不做 `watch`——在 rAF 里读一个普通属性不建立响应式依赖，代价为零；代价是间隔变更有一拍延迟，而流星间隔本来就是秒级。这也是全站唯一一处"天随人动"的耦合，最容易单独回退（删掉那三行即可）。
- 不要再引入这两条管线：黑洞/吸积盘/仪表环（已删除 `BlackHole.vue`）与红移坠入深度轨（已删除 `DepthRail.vue`；深度改由 `App.vue` 写 `--shift`）。
- **v3 定稿微调（1.0.0）**：变星移除外围圆环、呼吸幅度收窄并缓慢自转（`rot = t·0.22 + ph`）；流星与变星共用 `drawStar` 渲染器。
- **防饱和尾部渐隐（1.1.0）**：星轨即将转满前 20% 平滑暗化（`SETTLE_START=0.8`、`SETTLE_DEPTH=0.55`），另随机 1-2 根做柔和独立渐隐；每颗星带随机尾迹起点偏移（`shear`），使弧段截端错落、圆环连续无对齐断口；`FADE_0=0.008 / FADE_1=0.0032` 拉长尾迹，让相邻弧段衔接成连续同心圆环。
  - **2026-09-17「久了过饱和、要更透气」回收**：`SETTLE_DEPTH → 0.72`、`FADE_0 → 0.0104`、`FADE_1 → 0.0044`、`DEP → 0.0072`（稳态亮度 ≈ DEP ÷ fade，两头一起动才不会既变淡又变短）。
  - **2026-09-18 第二轮（`SETTLE_DEPTH → 0.6`、`FADE_0 → 0.0086`、`FADE_1 → 0.0038`、`DEP → 0.0084`）**：上一档收得太狠，用户改口"不明显、不好看"。现在 `DEP ÷ FADE_0 = 0.98`，**仍低于**当初被投诉过饱和的 1.06——因为这一轮补的是**对比**而不是整体提亮（见下条）。独立尾部渐隐同时加密到 **1-3 根 / 间隔 5.2~11s**（原 1-2 根 / 9~19s）：固定抽一两根久了会听出节拍。上面两组都是历史值，别照抄，以 `StarTrails.vue` 顶部常量块为准。
- **2026-10-07 第三轮：先修帧率耦合，再动数量与最深尾迹**。这次量的不是亮度而是**密度**：把 `accPass` 的合成数学离线复刻成按点积分（仿真器与逐帧暴力对拍，最大偏差 1.39%，含 60/120/144Hz 三档；尾迹闭式解与仓库里 `scripts/build_readme_art.mjs` 用的是同一条），再在 1920×1080 / 1440×900 / 390×844 三块屏 × 页顶/最深 × 60/120Hz 上读"沿半径每 100px 有几条亮线、亮线之间还剩多少黑"。
  - **根因不在口味常量**：`accPass` 里衰减乘了 `step`、星角走 `dtS`，**唯独每笔沉积的 alpha 不随帧时长缩放**——刷新率越高，同一点每秒被叠的次数越多，底片越亮越密。120Hz 上最深档：齿/100px 1.41→1.90、环间黑隙 27px→20px、顶到 α=1 的实心像素 0.76%→1.89%。**这就是前三轮"收了参数没见轻"的原因**：60Hz 上量出来的稳态值在高刷屏上不成立。修法是 `accPass(…, dep, step)` 把 `step` 也乘进沉积（星轨与变星两处）；60Hz 下 `step=1`，观感逐位不变，此后每个口味常量在任何刷新率上都落得准。

  - **细线串珠（同一天的第二批反馈："大屏上部分线条不连贯"）**：线宽 `lw = 0.6 + z·1.2` 的分布是 p10 0.80 / p50 0.96 / p90 1.41 CSS px——**55% 的星细于 1 CSS px**。旧写法 `dpr = min(2, devicePixelRatio, √(预算))` 在 1× 缩放的大屏上给出 dpr=1，于是中位星轨只有 0.94 个设备像素宽。按面积重叠积分量覆盖度沿弧的**谷/峰比**：0.94 设备 px 是 0.25（摆 3~4 倍 → 一串珠子带缝），**抬到"正好 1 px"是 0.27，等于没修**，1.40 是 0.53，1.87 是 0.79 且无低覆盖采样。所以底片内部分辨率加了 **1.8 的下限**（`sky.js` 的 `MIN_DPR`），预算同步从 4.6MP 抬到 9MP 以免被夹回去。这不是把线画粗——屏幕上物理线宽仍是 0.94 CSS px（画布降采样回 CSS 尺寸），多花的只是内部栅格：1920×1080 底片 2.07MP→6.2MP，每帧全屏 `destination-out` + `drawImage` 约 3× 像素量，**且只有 1× 屏才吃到这份代价**（2× 屏与手机本来就在上限附近）。被排除的另一条路是把线宽下限设成 `1.8/dpr`：墨量 ×1.73、98% 的星被加粗，等于把刚压下去的密度还回去，还会抹掉"亮星比暗星粗"那层尺寸差。

- **2026-10-07 第四轮：8 位底片的量化地板——"密度怎么收都不轻"的真因**。用户第三次点同一个问题（"密度还是很奇怪、部分断点太多、中心区显示有问题"，附 2557×1321 截图）。这次不改参数表，改成**逐帧复刻浏览器的算术**：700² 窗口、`Uint8` 底片、每帧衰减按 `round(α·(255−round(fd·255)))/255` 取整、每帧沉积按 `round(al·255)` 入射，跑 9000 帧（=150s，正好转满一圈）。
  - **机制**：只要 `α·fd < 0.5 LSB`，取整就把这一帧的衰减整个吞掉，那个像素**再也掉不下去**。地板高度 = 0.5/(255·fd)：页顶浅色 fd=0.0120 → 冻在 α≈0.17；最深档 fd=0.0073 → 0.27；而 09-18 那版 `FADE_1=0.0038` 时 `round(fd·255)=1` → **地板 α≈0.5**。于是每颗星 150s 扫过的一整圈永久留在底片上：实测残留覆盖 6.7% 像素、10 条半径行的角度覆盖率 >55%、最强一圈 **100%**，浅色上就是 Δ灰 32 的实线同心环。底片只增不减，多跑一分钟就更浓一档——**这才是前几轮"收了参数没见轻"的原因**（往下调衰减 = 往上抬地板），也正是"中心区显示有问题"：内圈环间距只有 9.6px，全糊成唱片纹。
  - **断点**：同一份算术里中位星的每帧沉积 `al = DEP·z = 0.0025` → **0.64 LSB**，四舍五入等于"有时加 1、多数加 0"，尾迹沿程被量化成一串补丁；再叠上线宽 0.96 CSS px 的抗锯齿边缘（覆盖率 ~0.3 → 0.2 LSB）**根本加不上去**，所以每根线的两侧是断的。第三处是 `SETTLE` 那道按角度统一削沉积的 72° 暗楔——所有半径在同一角度同时缺角。三者合起来读作"部分断点太多"。
  - **修法 = 沉积与衰减同时 ×20**（`DEP 0.0084→0.168`、`FADE_0 0.0086→0.172`、`FADE_1 0.0052→0.104`）：稳态亮度 `al/(al+fd)` 逐位不变，地板按 1/fd 掉到 **Δ灰 1.6**（最深档 2.5），每帧沉积升到中心 12.9 LSB / 线边缘 3.9 LSB。同一份 9000 帧重跑：残留覆盖 6.72%→**0.00%**、整环行 10→**0**、盖上镜头空转 10s 后均值 α 0.0109→**0.0009**。阴性对照：同样常数换 `Float32` 底片 → 残留 Δ灰 0.0，与 8 位那一臂差一个半数量级，说明差异确实来自取整而不是别处。半档（×10）实测 Δ灰 3.2 也过得了整环判据，选 ×20 是给 1× 大屏的抗锯齿边缘留余量。
  - **代价：尾迹长度不能再挂在衰减窗口上**（1/fd 从 83 帧掉到 4 帧，指数尾只剩 0.17°）。长度改由**弧长**承载：`accPass(…, len)` 里 `dthLen = (s.shear·len + dth)·boost`，live 传 `len = (flow·FADE_0/fade)^LEN_POW`，静态底片传 `PLATE_LEN`。压缩幂是刻意的——按 ω·T 线性放大会把最深档拉到 5.3 倍。
  - **`SETTLE` 两条一起删**（`SETTLE_START`/`SETTLE_DEPTH` 与只服务它的 `smooth01`）：它存在的理由是"临近转满别收成实心亮环"，而窗口缩到 4 帧之后闭合环根本不可能形成，留下的只有那道系统性暗楔。`FEAT`（随机 1-3 根独立渐隐）保留——它是随机的，不是全天一刀切。
  - **他看了：方向对，但"长度有点短，有点太空"**。上面预告的那条应验——地板没了之后实时底片只剩活尾迹，页顶档 齿/100px 只有 0.85、中位弧长 13.8°。回补走**两个正交旋钮**，不是把 ×20 退回去：⑴ **长度** = `SHEAR_MIN/SHEAR_SPAN/SHEAR_POW`（`0.06+r^1.25·0.34` → `0.09+r^1.25·0.85`，中位 13.8°→26.0°，r=600 处 145px→272px）；⑵ **数量** = `N_BIG/N_SMALL`（180/100 → 280/140，齿/100px 0.85→1.63、黑隙中位 115px→51px、可见亮线覆盖 0.64%→1.88%）。这三个数现在是有名字的常量、`scripts/build_readme_art.mjs` 从源码读它们（此前 shear 在源码与配图脚本里各写一份，是个真的分叉口）。

- **2026-10-07 第五轮：深色的"灰色轨迹"不是残留，是每条线自己的抗锯齿翼——星数必须分主题**。用户第四次反馈，这次指"圆圈尾部消失后底部的灰色轨迹太脏乱了"（附 2020×1225 深色截图）。先怀疑 ⑭ 那个 8 位地板没清干净，量完否掉了：**深色档地板实测只有 Δ灰 1.5（最大 1.7）级**（`quant-plate.mjs` 加 `DEEP=1` 分支后重跑：fd=0.1720、每帧沉积 8.6 LSB、幽灵环中位 α=0.0079），而他截图上那片灰**实测在 7.0 级**、带宽 4~9px——差 5 倍，不是同一层东西。

### 3.2 曝光深度与时间流速

- 滚动 = 曝光加深，进度 `p∈[0,1]` 由 `App.vue` 写入 CSS 变量 `--shift`，驱动：暗角晕影加深、首页宣言字距随潮汐力拉长。同一个值另镜像进 `src/lib/shift.js` 的 `shift.v`，供需要**在 JS 里每帧读**的消费方使用（次级页画布的曝光深度，§3.1）——CSS 变量读回来要走一次 `getComputedStyle`，放进 rAF 等于每帧一次样式查询。`--shift` 与 `shift.v` 由 `applyShift()` 同时写，不存在第二个来源。
- **fall 转场**：路由跳转 = 一次下坠重开 → 展开成新页。全站唯一的内容转场。
  **2026-09-18 把权重从"缩"挪回"化"**：进入方 `0.44s cubic-bezier(0.52, 0.04, 0.24, 1)`、`scale(0.88) blur(15px) → 正常`；离开方 `0.26s cubic-bezier(0.36, 0.1, 0.6, 0.42)`、`→ scale(0.9) blur(12px)`。两个理由：⑴ 旧曲线 `cubic-bezier(0.16, 0.84, …)` 起步斜率高达 5.25，**虚化在前约 60ms 就散光了**，剩下的 0.36s 只是在盯着一个缩放看——慢起的 S 型让模糊留到中段才化开，两页重叠的那 260ms 才真的是叠影；⑵ 旧曲线末端（`ease-in`）是"先定住再猛抽"，换成有限末端斜率。`scale` 起点 `.8→.88` 是为了削弱几何跳幅，模糊 `12→15px` 补回失去的存在感。
  关键帧里的 `filter` 作用于**整页子树**，每一帧都要重新栅格化，且离开方与进入方并行叠影时更甚——这是本站最贵的一处绘制。1.2.0 曾评估改为"只动 opacity/transform + 独立红移覆盖层"，实为可行但**叠影模糊正是"坍缩"的手感来源，最终决定保留原样**。本轮时长只从 0.42s 放到 0.44s，代价 +20ms 的整页栅格化，可接受。
- 文章页正文末尾原先那枚「时间膨胀」手记（`τ/t = √(1−1/r)`，配文"你在此处停留的光阴，比人间慢一拍"）**2026-10-10 删**：字数与时长本来就在页眉读着，那行只是把同一件事说成诗。

### 3.3 暗带契约：天空与文字的位置协议

**一句话**：文字底下的天空必须被压低，天空只在带外才全亮——这件事**全站只做一处**，不外包给每张卡片。

这条契约是"P1 可读性收敛"的落点，解决的是实测出来的问题（不是审美分歧）：改之前 11 个次级页里只有文章页做过可读性底板，其余各凭运气，同一套文字色在实际合成底上的对比度是——

| 文字底下的实际情形 | text-0 | text-1 |
| --- | --- | --- |
| 裸星轨（Projects / Records / Updates / About 等） | **1.7:1** | 1.1~1.8:1 |
| 44% 卡片压在星轨上（Blog / Wall / Admin） | 4.5:1 | **1.5:1** |
| 文章页 88% 玻璃底板 | 15.7:1 | 5.4:1 ✓ |

即**同一站点内，文章页接近 AAA、列表页不到 AA 的三分之一**。这就是"阅读困难 + 体验割裂"的数值形态。

- **为什么不能靠加卡片遮罩解决**。把星轨压回可读所需的遮罩 alpha 解出来是 **81~85%**——那时候卡片等于不透明，天空白画，"长曝光"这个核心装置在列表页就名存实亡了。顺带实测到另一件事：卡片填充相对天空底**只有 1.04~1.14:1 的表面比**（肉眼几乎不可辨），卡片的边界感一直来自 `--card-brd` 那根发丝线；原先 44%→72% 的 hover 填充跳变更是只有 1.05:1，等于没有。所以 `--card-*` 重定标为「填充只管分组、悬停强调交给边线与 `.neo-spike`」（52% / 62%，是**实测区间内的口味值**，不是算出来的）。
- **三个令牌的分工**：几何在 `neo.css` §1 共享块（`--sky-band: min(1120px, 100%)`、`--sky-feather: calc((100% - var(--sky-band)) / 2)`），**压低系数分主题**在 §2/§3 各定一档（`--sky-k`）。带宽对齐 `.neo-shell` 的 `max-width: 1120px`，保证正文整块落在带内；羽化段自适应地吃掉带外的全部余量，因此不存在"内容比带宽、卡片边缘落在羽化段上过亮"的窗口。
- **两套主题的 k 是怎么解出来的**。取**最差那一档星轨色**（深色是琥珀 tier2 `#ff977d`，浅色是 tier1 墨迹 `#51240e`）在**峰值 alpha 0.753** 下合成出文字底，要求最小的次要文字 `text-1` 也过 AA 4.5：深色解得 k ≤ 0.2 → 取 **0.15**（实测 5.48:1，留 22% 余量）；浅色解得 k ≤ 0.06 → 取 **0.06**（4.65:1；k=0.1 只有 4.40，不达标）。**按峰值而不是中位数（0.247）算是必须的**：星轨在动，同一枚文字像素的底随时间明暗波动，按中位数设计等于放任它闪烁出界。浅色比深色严 2.5 倍，因为那里压的是接近纯黑的 `text-0` 与中性 `text-1`。
- **实现落点**：渐变本体在 `StarTrails.vue` 的 scoped `.st-fixed` 上（次级页那块 `position: fixed` 画布），叫 `--_sky-mask`；它消费的三个令牌 `--sky-band` / `--sky-feather`（`neo.css` §1）与 `--sky-k`（§2/§3 各一档）都在令牌层。`mask` 走 alpha 模式，故 `rgba(0,0,0,var(--sky-k))` 的 alpha 就是"天空保留多少"。选画布而不是选页面容器有两个硬理由：⑴ 一块画布服务全部 9 个次级页（isSub = path 不等于首页），改一处即全站一致；⑵ 画布在 `main` **之外**，不会像文章页进度线那样被 `fall` 转场期间页根的 `transform` 抓去当包含块。不支持 `mask-image` 的浏览器等于回到改前状态（可读性不达标但不会画错），属优雅降级。首页那台 `.st-abs` **不进这里**——它是主视觉，压暗带等于把盘子本身压掉一半；它的文字对比由 `.title` / `.manifesto` 自己的 `--ink-0` `text-shadow` 柔光承担（首屏那条 `--scrim` 白纱已撤，见「首页」条）。
- **固有取舍，别当缺陷报**：视口 ≤1120px 时羽化归零，即**窄屏上一次级页的天空被整片压低**（浅色主题下几乎看不见）。手机屏上没有横向余量可留给天空，这是几何事实；大气感由首页那台不加遮罩的相机、以及宽屏两侧的侧廊承担。若日后要在窄屏找回天空，方向是给它一条**纵向**出口（顶部条带），而不是调大 `--sky-k`——那等于把可读性换回去。
- 卡片/玻璃/暗带三者的关系收敛为一句话：**暗带管"读得清"，卡片管"是一组"，文章页的 `.neo-glass` 管"长时间阅读时的隔离"**。前两者不再是同一件事。

| `--panel-frost-bg` | 底板在无 `backdrop-filter` 时的兜底 | `rgba(2,2,4,.78)` | `rgba(245,242,234,.78)` |

> **注意**：凡是"跟随底色"的语义色都必须在两套主题里各自定义。`--scrim` 深色用深底色、浅色用纸色，**不要在浅色上复用深色的 `rgba(2,2,4,…)`**；未定义会让使用处的 `var(--scrim)` 整条声明失效（首页文字底衬即由此消失）。同理 `--shadow` 深色是近黑、浅色是暖深色——用浅色的 `--ink-2` 当阴影会在浅色上晕出一圈浅色光斑（文章页阅读底板曾如此）。
>
> **1.2.0 删除的死令牌**：`--glass-bg` / `--glass-brd` / `--glass-blur` / `--hole` / `--signal-canvas` —— 全站已无消费方。玻璃只剩抽屉一处（用字面量 `blur(24px)`），其余表面改用高不透明实底。

### 4.3 字体三层（展示层自托管子集）

| 层 | 变量 | 栈 | 用途 |
| --- | --- | --- | --- |
| 标题碑刻 | `--font-display` | **`EN Display Serif`（自托管子集）** / `Songti SC / Noto Serif SC / Noto Serif CJK SC / Source Han Serif SC / Source Han Serif CN / STSong / SimSun` | `.neo-title` `.neo-h2` `.neo-prose h2…h4` |

普通 UI 文字用 `--font-sans`（`PingFang SC / Microsoft YaHei / system-ui`），为 body 默认字体。

**为什么只有标题层自托管**：中文衬线三平台没有共同系统字体（macOS 命中 Songti SC，**Windows 会落到 SimSun**），
而 `--font-display` 最大到 132px，品牌观感全压在这一层；正文用系统宋体栈既合格又不付下载代价。

**子集怎么来**：`@font-face` 声明在 `neo.css`，字体与许可在 `src/assets/fonts/`，由 `npm run font:build`
（`scripts/build_font.mjs`）从本机 Noto Serif SC 可变字体生成 —— GB2312 一级字表 3755 字 ∪ 仓库现有内容
用字（当前 3922 字 ≈ 703 KB），并 `wght=700` 实例化（展示层元素全部为 700，单实例体积最小）。
字表改为「仅内容用字」可压到约 174 KB，代价是新文章的标题字可能单字回退。

**两条约束**：① 产物必须提交，构建与 CI **不调用**该脚本（因此不依赖源字体）；② 该族只有 700 一个字面，
新增 `--font-display` 消费方若不显式写 `font-weight: 700`，会直接以这个 700 字面渲染。

## 8. 页面要点

- **首页**：`HorizonHero.vue` 排版层浮于星轨之上，**水平居中、整块上提**。`h1.title` 是站名 `N.heroTitle`（`ESCAPING NOTES`），进场逐字打出（260ms 起笔、每字 82ms），光标 `.caret` 用 `--cold`（光标属交互）；**打满后再闪 1.5s 就淡出退场**——一枚永久闪烁的竖线读起来像没加载完，不像标题，减弱动效下干脆不出现。`ready` 之前宣言两行的 `animation-play-state` 一直是 `paused`（暂停期间连 `animation-delay` 的钟都不走），打满才放行。中英主次：两行要读成一个 lockup 而不是"大标题 + 小副标"——站名 `clamp(22px,4.2vw,60px)` 配 `0.18em` 字距，十六字宣言 `clamp(18px,3.0vw,38px)`（≈1.6:1，且两行宽度接近：英 ≈12.6em / 中 ≈18.4em）、基线字距 `+0.08em`（负字距是英文排版的遗留，汉字粗宋会互相咬）、行高 1.9、两行间距 `--space-3`——站名是第一眼，但那十六个字才是有分量的一句。整块不再垂直居中：`.hero-text` 底部垫 `clamp(64px,19vh,210px)` 把块心抬进天空重心（峰顶占视口 ≈62%，居中时联句几乎贴到山尖；13→16→19vh 是他逐版要求再提），窄屏垫量收一档（2026-10-09）。同日试过系统手写体栈（Segoe Script 等）被他判"不好看"当日撤回，未留新令牌。底衬那团柔光已全部撤除，首屏文字只靠 `.title`/`.manifesto` 自己的 `--ink-0` `text-shadow` 立着。首屏地景是一条**地平线横带**（`.hero-plate`，`top:46%`）：照片只占下沿，上半屏整片空出来给标题与星轨。**淡出不在 CSS 里，烘在素材里**——`build_plate_bg.ps1` 取原图 700~2560 行，在山脊（峰顶实测 1120 行，读自 25px 网格渲染）以上盖一层竖向天空纱，顶端正好落在 `--ink-0`、到峰顶收敛为 0，所以山一寸没被遮；CSS 侧配 `background-position: 50% 0`，把素材第 0 行永远钉在横带顶边，边界两侧同色。原先的 `mask-image` 是在 105px 内把照片落在边上的 `#9FB4CB` 插到页面色 `#F2F5F9`——两端颜色不等，那条横杠就是这么来的——**这是颜色问题不是长度问题**，拉长渐变只是摊开同一段色差，两端不等照旧。换法之后实测：边界差 1/765 通道和，淡出跨 220px，进入段每 20px 降 0.021 亮度（原 0.098）。同处还压过一层 45% 的 `--scrim` 白纱，它把山脚从 `#334974` 抬到约 `rgb(118,133,163)`、与照片自己的天空同亮度——山没有落点，那是「上下割裂」的另一半，已删（`--scrim` 由此零消费方，两套主题仍各自定义着，退役要两处一起删）。暗色 `--hero-img` 复用抽屉那张压暗版，顶端 `#090E14` 对 `#020204` 只差 1.07:1，本就看不见缝，故没有单独烘暗版首屏。首屏视差随滚动下沉淡出。
- **首页折线以下**：风景底片是挂在 `App.vue` 上的 `.sub-plate`（`position: fixed` 铺满视口；`HomeView.vue` 里那条 `.plate` 样式是**死码**——模板里没有对应元素，等组件去前缀那一批一起清）。素材由 `npm run bg:build` 从 `plates-src/` 的原图烘出来，原图不进仓库。**底片现在是清晰的**：预模糊（原 `BLUR_DRAWER=13`）与 42% 的 `--ink-0` 平纱都已撤，糊不糊改成运行时参数 `--plate-blur`（0–12px 滑杆，**初值 12 = 拉满**，见「设置卡」条；素材一律出清晰版，所以滑杆两端都有实义，0 那一档是真清晰）。五张轮播**每张 10s**：`--plate-cycle: 50s`，父层那张 + 四个 `.sub-plate > i` 共用**一条** `plate-slot` 关键帧、只靠 `animation-delay`（9/19/29/39s）错开——每张独占 9s、两端各 1s 与邻张交叉，延迟取"10s 的倍数减 1s"正是为了让一张的淡出与下一张的淡入落在同一秒上。加一张要动三处（模板多一个 `<i>`、多一档延迟、`--plate-cycle` +10s），且关键帧的 2%/20%/22% 是按 50s 一圈算的，改了周期就得重算。减弱动效下停成单张不轮播。
  可读性这条要连代价一起写清：撤掉平纱后底片上**只剩一条竖向渐变**（`transparent 18% → --ink-0 78%`），它管页尾与折线附近，不再管整幅。2560×1392 下沿内容列（x 720–1840、y 120–1086）对**当时那三张**浅色底片逐点合成的最坏值——落在卡面上的 `--text-0` 是 **5.5:1**（`--card-bg` 从 52% 抬到 72% 则 9.65:1），而**直接压在底片上的裸字只有 1.0–1.2:1**。裸字在撤纱之前也只有 1.64:1（`--text-1`），本来就不达标，平纱只是把它藏住了。试过把这一条渐变改成"上下双纱、中间留清晰窗口"与"顶部淡入 + 原斜坡"两种形状，裸字最坏点仍卡在 1.0–1.8:1 上不去——**无纱的风景照片上放裸字到不了 AA，与渐变的形状无关**。所以次级页顶部那三行裸字（`.neo-eyebrow` / `.neo-h2` / `.neo-lede`）是另案的债，别再指望加一层纱把它糊过去。
  **上面那组数没有按五张重算**（2026-10-10 抽屉改成五张轮播）。先量了五张烘完素材的整体亮度（48×32 网格采样、`meanL` 归一到 0–1）：`paper1 0.472 / paper3 0.346 / paper4 0.301 / paper5 0.890 / paper6 0.510`。新添的最暗那张 `paper4` 只比原来最暗的 `paper3` 低 0.045，而卡面是 52% 的半透底、底下就是这张照片，所以那枚 5.5:1 会随底片变暗往下走一点，幅度未测；另一端 `paper5` 亮到 0.890，几乎贴上一页底色 `#F2F5F9`（≈0.95），裸字压在它上面只会比原来好读。逐点合成留给下一次连同那三行裸字一起办。
