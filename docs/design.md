## 1. 核心概念

首页是一台架在三脚架上的相机在长曝光：数百条星轨弧绕一枚偏心天极刚体旋转累积，恒星周日视运动是全场一致的时间流速（其上叠一层不可通约的慢呼吸）。文章从折线以下的抽屉进入。色彩取自夜空的两副面孔——深色为冷白/暖白/琥珀，浅色为板岩/石墨/朱砂；色温跟星等走（暗星冷、少数亮星抽暖），冷暖分工不混用；山体在地景横带内沿脊线遮挡星轨。滚动即曝光加深：晕影收紧、天空转快。

访客一句话复述：**"这是一个把博客做成相机长曝光的网站，滚动就是这一夜在加速。"**

## 2. 设计原则

所有后续决策都要遵守这五条。

1. **冷暖分工，严格不混用。** `--cold`（冷）只用于**交互**：hover / 链接 / 焦点 / 星轨节点 / 打字机 caret / 标签。`--hot`（热）只用于**深度与强调**：进度 / 主动作按钮 / 日期 / 当前项 / 朱砂点睛 / 正文 h2 左缘。`--white` 只用于**星核高光与 ≤2px 高光**（光子环、按钮扫光），不铺大面积。
2. **主题是叙事，不是皮肤。** 切换主题 = 一次夜拍（深色）或一次显影（浅色），由 `src/lib/theme.js` 驱动 `data-theme`。任何新增样式必须在两套主题各看一遍。
3. **深度 = 时间。** 滚动把 `--shift`（0..1）写入 `<html>`，驱动晕影收紧、首页字距被潮汐拉长、星轨提速。凡"随滚动变化"的视觉都挂在 `--shift` 上，不各自写死。
4. **界面文案唯一来源是 `narrative.js`。** 视图里不出现硬编码文案（眉标、按钮、提示、空态尤其）。删 `N` 里的字段是**静默失败**：Vite 不为取不到报错，它渲染成空文本。
5. **可降级。** 一切动效都要有 `prefers-reduced-motion` 分支；API 不可达时站点仍是完整的离线镜像——"没连上"永远显示 `--` 而不是 0（§8 关于页）。

## 3. 两个核心装置与一条位置协议

### 3.1 长曝光星轨（`src/components/StarTrails.vue`）

**概念。** 首屏 = 架在三脚架上的相机长曝光。恒星周日视运动是刚体旋转（全场一致 `ω≈0.042 rad/s`），绕偏心天极（全站同一处：视口 `0.5 / 0.38`）累积成同心弧。刚体旋转只保证几何正确，不保证好看——可读的星空靠星等分层（多数暗、极少数亮）与弧长错落。恒定 ω 之上叠一层 `gust = 1 + 0.22·sin(t·ω_g)·sin(t·0.37ω_g+1.3)`（`GUST_*`，主周期 ≈47s，两个慢波不可通约、几分钟内不重复）破节拍器感；全场共享同一个 gust，不做差速旋转。

**极点为什么全站统一。** 两台相机极点不同，导航后同心弧的圆心会跳，"同一片天"当场穿帮。更早是 `0.62/0.38`（偏右上，给当年贴左下的宣言让位），首屏改居中排版后回到水平正中。

**渲染管线（Canvas 2D · 累积缓冲）。** ACC 离屏底片按**视口**尺寸分配、全站共享，每帧不清空：① 衰减 pass——`destination-out` 填 `alpha=fade`；② 增量 pass——每星画本帧短弧，**弧长由 `shear` 主导，不是 ω·dt**（每帧只有 0.0007rad）。这一条最容易记错：调 ω 改的是天空转多快，改弧长要动 `shear`。亮星（`z>0.62`，实测占 14.2%）另在拖痕前沿叠一笔 22% 长、0.72 倍线宽、`HEAD_GAIN=2.6` 的短弧，让亮度自尾向头递增（实测累积比 1.3~1.6 倍）——等亮的长弧在视觉上只是"一根光棒"。主画布每帧 = 底 → `drawImage(ACC,0,0,W,H)`（顺带把天区坐标缩放进本机盒子）→ 当帧层（流星，不累积，保持锐利）→ 首页相机末尾 `destination-in` 山脊遮罩。底片内部分辨率 `dpr = min(2, max(1.8, devicePixelRatio), √(9e6/(w·h)))`，9MP 是预算封顶，相机跟随底片 DPR（这条为什么现在看是纯代价：§9 第 9 条）。

**天与相机（`src/lib/sky.js`）。** 底片像素、星群、天极、时钟、取景权放在模块级单例里——**星空是一份，相机是两台**。四条承重：

- `ensurePlate()` 只在**视口尺寸或 DPR 变化时**新建底片。桌面换页两者都不变，于是同一张底片继续感光——这是"一夜连续曝光"从口号变成实现的唯一一处改动。移动端会变（地址栏收放改 `innerHeight` → `resize` → 走重开分支），所以重开前把旧底片搬进新底片，**且必须是相似变换**（绕旧极点等比缩放 `s = 新maxR/旧maxR`，再把旧极点平移到新极点）：按 x/y 两轴各拉伸一次会把已感光的弧压成**椭圆**——滚动条一出现 `innerWidth` 少 ~17px，在 r=1601 的弧上圆度误差就有 10.6px（肉眼直接读出"不是正圆"），手机地址栏 100px 的高度变化误差 61px，桌面从 1920×1080 拉到 2557×1300 是 157px。相似变换的圆度误差恒为 0；极点按新尺寸重算带来的一两度漂移仍在——**漂移可接受，黑屏和椭圆不可接受**。
- `sky.t0` 全站起一次，星角 `s.th` 因此跨路由连续；组件卸载只 `releasePlate(self)` 交还取景权，**不把 `acc` 置 null**（那正是过去每次导航重铺底片的根因）。
- **取景权只管沉积，不管重绘。** `fall` 是并行转场，离开方与进入方并存约 260ms，两台相机同时沉积会画双份、`resize()` 还会互相清屏，所以底片同一时刻只认一个主人，后挂载者接管。但 `ownsPlate()` 只包住 `update()` 里的沉积段，非主人照样每帧 `draw()`——早期把它写进 `tick()` 的停帧条件，交出底片那台就在淡出的 260ms 里**冻在半帧上**，那是"切换顿挫"的真来源。如今星轨只剩首页一台相机，这段互斥实际不会触发，留着当护栏。
- **两台相机的盒子一律取视口**（`resize()` 里量的是视口，不是 hero 的盒子），所以天区与相机恒为 1:1。这不是巧合：首页 `.hero` 是 `100svh`，手机上比 `innerHeight` 小最多 ~17%，拿它当相机会把底片**非等比压扁**——同心弧在首页变椭圆、进文章页又跳回正圆。多出来的一截由 `.hero{overflow:hidden}` 裁掉，牺牲几十像素取景换几何不出错。

**Props。** 只有一个：`interactive`（Boolean，默认 `false`）。`true` 才启用流星/指针层与 `--lx/--ly` 时间膨胀；`false` 无交互层、限帧 30fps，只作活背景。**星数与之无关**——星群属于全站共享的天空（按视口宽与主题定数，深色再乘 `N_DEEP_K`），次级页若少沉积一半星，那些圆弧会在阅读中因全局衰减慢慢消失。

**交互语义。** 滚动 = 时间流速（`flow = 1 + k·2.2`，`fade` 由 0.172→0.104；尾迹长度按 `(flow·FADE_0/fade)^LEN_POW` 放大弧长，`LEN_POW=0.28`），所以越深天越快、弧也越长。指针 = 引力时间膨胀（180px 半径内转速 ×2.8、提亮、轨迹局部卷曲，移开恢复）。次级页也吃滚动深度，但走**文档级**：`update()` 每帧读 `src/lib/shift.js` 的 `shift.v`，推进 `flowT = 1 + d·SUB_FLOW`（`SUB_FLOW=1.1`，首页 `FLOW_MAX` 的一半，阅读时保持克制）与 `fadeT = SUB_FADE_TOP − d·(SUB_FADE_TOP − FADE_1)`（`SUB_FADE_TOP = FADE_0·1.3`）——页顶是安静的短尾迹，越往下读曝光越久。不用首页那套 `scrollY/(H·1.1)`：长文章滚过一屏后者就饱和了，读不出整篇进度。

**星等三档（72/22/6）。** 暗/中/亮各走自己的 z 区间（0.10–0.32 / 0.34–0.64 / 0.75–1.0），线宽（亮 ×1.35）、弧长（亮 ×1.5、中 ×1.15）、沉积系数（`dk` = 0.8/1/1.5）全分档——**档间差要大于档内抖动**，结构靠少数粗长亮拖痕承担。亮星外圈另叠一笔宽而淡的同弧（`bleed`：lw×2.6、α×0.16）：浅色读成干版墨晕，深色 `lighter` 下读成辉光，一笔两主题各取所需。色温跟星等走（暗=冷档、中=中性档、亮星里三成抽暖档），暖色只跟在亮星后面，出现即点睛。累积稳态 alpha ≈ `al/(al+fade)`，实测从暗到亮 0.196 → 0.247 → 0.443 → 0.753。

**半径分层。** 独立随机取样必然结块：180 条环 12 次取均值实测"最挤 10 条跨度 ÷ 最松 10 条跨度"= **5.66**、最小间距 **0.0px**、50 个半径桶 **2.6 个全空**。改为**等距槽 + 槽内抖动 0.76 + 单调弯折**（`pickRn(i,n)`，`MID_BIAS=0.2` 保留"中段略密"的倾向）：结块比 **1.65**、最小间距 1.5px（n=100 时 3.2px）、空桶 1 个（天极附近，本来就该空），而相邻间距仍有 ±76% 摆动，不是尺子画的。

**弧长与闪烁。** `shear = 0.07+r^1.55·1.0` × 星等倍率（亮 1.5 / 中 1.15 / 暗 1）：中位 ≈23.6°、最长 ≈61°、亮星到 92°，最短最长差 8 倍以上——随机感首先靠"每根都不一样长"承载。闪烁幅度随星等放大（`ta = 0.08+0.13·min(1,z)`），另叠云幕慢包络（周期 40–110s、幅度 10–22% 缓变暗化），与快闪烁、独立尾部渐隐（`FEAT`，同时只挑 1–3 根、间隔 5.2~11s）构成三个时间尺度。

**主题。** 深色 = 冷白（暗）/暖白（中）/琥珀（亮星点睛），`lighter` 发光；浅色 = 板岩（暗）/石墨（中）/朱砂（亮星点睛），`source-over`，fade×1.4 尾迹更干净。**浓淡常量分主题，不共用一个数**：沉积浅色 ×1.5、深色 ×1；衰减浅色 ×1.4、深色 ×1；星数深色 ×`N_DEEP_K`(0.65) → 深色 182 根 / 浅色 280 根。换主题才"换一张底片"（防串色），并且**要连带重播星群**（星数变了）：`readColors()` 拿 `data-theme` 与 `sky.theme` 比对，相同就直接返回——两台相机各挂一个 MutationObserver，一次切换会进来两趟，靠这个比较幂等。**挂载不重铺。** 换主题同时重建山脊遮罩（两个主题的地景是两张不同的照片）。

**山脊遮挡（`src/lib/ridge.js`）。** 山只存在于首页地景横带，而底片全站共享，所以遮挡只能做在**绘制时**、按相机裁——沉积时切弧会让次级页在同一张底片上读出一圈缺角。遮罩是一张半分辨率 alpha 画布：脊线以下 0，脊线以上 `RIDGE_FEATHER=26px` 羽化到 `RIDGE_ALT_FLOOR=0.62`，再往上 `RIDGE_ALT_K=0.22` 个视口高回升到 1（后半段是大气透视：贴地平线的星轨本该比天顶淡，顺带把边界做成梯度而不是剪纸边）；整条边界再上移 `RIDGE_BIAS=10px` 给描线误差留余量。`draw()` 末尾一次 `destination-in` 合成，流星同裁——它们都是天空的现象，本该躲在山后。轮廓是在 bake 产物网格叠图上手工描的折线；两套主题共用同一张首屏取景，所以**只有一条**。cover 变换（水平居中、垂直顶边钉死）在 `buildRidgeMask` 里复算，盒子取 `.hero-plate` 自己的 `getBoundingClientRect`——按视口高固定比例算会踩 `100svh` 与 `innerHeight` 在手机上的差，而横带高度本身也不是常数（§8「首页」的 `--band-h`）。**换 bake 源（`SRC_HERO`）必须重描这条折线。**

**流星。** 每 6–9s 随机落一颗，单颗活 900ms，同时在场最多 8 颗；入射带 0.40 视口高、速度 900–1500 px/s、尾迹 0.24s、头 α 0.95、线宽 1.6。`update()` 在生成下一颗的时刻读 `music.playing`（`src/lib/music.js`）：在响则把间隔压向最短值（区间长度 ×0.4），停下后**下一次生成**即自然回弹。刻意不做 `watch`——在 rAF 里读一个普通属性不建立响应式依赖，代价为零；代价是间隔变更有一拍延迟，而流星间隔本来就是秒级。这是全站唯一一处"天随人动"的耦合，最容易单独回退（删掉那三行）。

**限帧与停帧。** 非交互模式目标 30fps（`SUB_FPS`），不足一帧间隔时 rAF 回调直接返回、不绘制；`update()` 用真实 `dt`（≈33ms），所以转速与满帧完全一致，只是全屏 `destination-out` + `drawImage` 的绘制量减半。两道停帧闸门只看 ① `document.hidden`（`visibilitychange`）② `onScreen`（**仅首页相机**：hero 在流内，整块滚出视口后没人在看；`IntersectionObserver` + `rootMargin: 200px`，回滚时不会先撞上一帧停滞的画面；次级页相机是 `position: fixed` 满屏，恒在视口内，不需要观察）。停帧期间星角冻结——等价于镜头盖上时不再曝光，回到视口后按 `dt ≤ 48ms` 的上限续长，不会跳变。**取景权不是闸门**（见上，它只关沉积）。

**惯性常数 `0.94`。** `flow` / `fade` / 指针光锥都按 `1 - 0.94^step` 向目标推进，约 1 秒收敛（早先是 `0.9` ≈ 1/3 秒，改滚动速度的瞬间天空会"弹"一下）。

**降级。** `prefers-reduced-motion` = 一次性快进 380 步生成静态底片，不启动 rAF；由 `ensureStaticPlate()` 按 `sky.plateBuilt` 保证**每张底片只冲一次**，换页与第二台相机都不重冲。静态底片的弧长倍率 `PLATE_LEN` 与 live 的 `len` 是两条值（它与 shear 相乘，一边长另一边就要收）。

**部署位置。** 首页由 `HorizonHero` 以 `interactive` 挂载；次级页由 `App.vue` 以非交互模式挂载为活背景；两者看同一张底片。

**离线复算。** `scripts/build_readme_art.mjs` 与 `scripts/check_contrast.mjs` 复刻同一套合成算术（三档、`dk`、云幕、bleed、色板），常数**从源码正则读**、读不到直接抛错——所以改星轨参数后要重跑 `npm run art:build`；两张 README 底片图的星数按主题各算（280 / 182）。量密度的方法：复刻 `accPass` 合成数学、同步跑固定帧数、`getImageData` 量底片（rAF 冻结也能跑）；深色与浅色各跑到 2400 帧，`p50` 全程钉在 0.247 / 0.165、最亮在 0.68~0.83 之间不爬向 1，即覆盖面积翻 3.6 倍的过程中**没有饱和回归**。

### 3.2 曝光深度与时间流速

- 滚动 = 曝光加深。进度 `p∈[0,1]` 由 `App.vue` 的 `applyShift()` 一次写入 CSS 变量 `--shift`（驱动暗角晕影、首页宣言字距），同时镜像进 `src/lib/shift.js` 的 `shift.v` 供**需要在 JS 里每帧读**的消费方（次级页画布的曝光深度，§3.1）。为什么要两份：CSS 变量读回来要走一次 `getComputedStyle`，放进 rAF 等于每帧一次样式查询。两者由同一个函数写，不存在第二个来源，**也不许有第二个滚动监听**（`scrollHeight` 会强制同步布局，绝不能每帧读）。
- **`fall` 转场**：路由跳转 = 一次下坠重开 → 展开成新页，全站唯一的内容转场。进入方 `0.44s cubic-bezier(0.52,0.04,0.24,1)`、`scale(0.88) blur(15px) → 正常`；离开方 `0.26s cubic-bezier(0.36,0.1,0.6,0.42)`、`→ scale(0.9) blur(12px)`。不用 `out-in`，重叠的那 **260ms** 两页同时在场、都带模糊，叠影就是这层影。曲线为什么这么选：旧曲线 `cubic-bezier(0.16,0.84,…)` 起步斜率高达 5.25，**虚化在前约 60ms 就散光了**，剩下 0.36s 只是在盯着一个缩放看；慢起的 S 型让模糊留到中段才化开，末端也换成有限斜率（旧的是"先定住再猛抽"）。`scale` 起点 `.8→.88` 削弱几何跳幅，模糊 `12→15px` 补回失去的存在感。
- 关键帧里的 `filter` 作用于**整页子树**，每帧重新栅格化，两页并行叠影时更甚——这是本站最贵的一处绘制。评估过改成"只动 opacity/transform + 独立红移覆盖层"，可行但**叠影模糊正是"坍缩"的手感来源**，按取舍保留原样（§9 第 12 条）。
- 底片跨路由常驻之后，换页只剩 `fall` 一处转场。

### 3.3 暗带契约：天空与文字的位置协议

**一句话**：文字底下的天空必须被压低，天空只在带外才全亮——这件事**全站只做一处**，不外包给每张卡片。

这条契约解决的是实测出来的问题（不是审美分歧）。改之前次级页里只有文章页做过可读性底板，其余各凭运气，同一套文字色在实际合成底上的对比度是：

| 文字底下的实际情形 | text-0 | text-1 |
| --- | --- | --- |
| 裸星轨（Projects / Records / Updates / About 等） | **1.7:1** | 1.1~1.8:1 |
| 44% 卡片压在星轨上 | 4.5:1 | **1.5:1** |
| 文章页 88% 玻璃底板 | 15.7:1 | 5.4:1 ✓ |

即**同一站点内，文章页接近 AAA、列表页不到 AA 的三分之一**。这就是"阅读困难 + 体验割裂"的数值形态。

- **不能靠给卡片加遮罩解决**（§9 第 1 条）。顺带量到另一件事：卡片填充相对天空底**只有 1.04~1.14:1 的表面比**（肉眼几乎不可辨），卡片的边界感一直来自 `--card-brd` 那根发丝线；原先 44%→72% 的 hover 填充跳变更是只有 1.05:1，等于没有。所以 `--card-*` 重定标为「填充只管分组、悬停强调交给边线与 `.en-spike`」（52% / 62%，**实测区间内的口味值**，不是算出来的。这组数当年是卡面的 resting 档，2026-10-11 起 resting 改成不透底、52/62 归给「半透明」那一档，见下面第三条）。
- **三个令牌的分工**：几何在 `site.css` §1 共享块（`--sky-band: min(1120px, 100%)`、`--sky-feather: calc((100% - var(--sky-band)) / 2)`），**压低系数分主题**在 §2/§3 各定一档（`--sky-k`）。带宽对齐 `.en-shell` 的 `max-width: 1120px`，保证正文整块落在带内；羽化段自适应吃掉带外全部余量，因此不存在"内容比带宽、卡片边缘落在羽化段上过亮"的窗口。
- **卡面的 resting 档是不透底**（作者 2026-10-11 定的口味；实现见 `src/lib/surface.js` 与 §4.2 的 `--card-solid` 行，设置卡「卡片颜色」里可翻回半透明）。这**不改上面那条契约**：读得清依旧归暗带管，52%/62% 那组值整组活着，只是从"默认"变成"另一档"。要连代价一起认：不透底把底片完全挡在卡面后面，那张照片本来就没参与可读性，但它参与大气感——默认档一落地，次级页的风景就只剩卡片之间的缝隙（浅色下 `--text-1` 从压页底的 5.84:1 升到压纯白的 6.39:1，深色下反过来从半透的 6.13:1 降到不透底 `--ink-1` 的 5.98:1，两档都过 AA；即这一档在深色里买的是"实板"不是"更好读"）。
- **两套主题的 k 怎么解出来的。** 取**最差那一档星轨色**（深色是琥珀档 `#ff977d`，浅色是 tier1 墨迹 `#51240e`）在**峰值 alpha 0.753** 下合成出文字底，要求最小的次要文字 `text-1` 也过 AA 4.5：深色解得 k ≤ 0.2 → 取 **0.15**（实测 5.48:1，留 22% 余量）；浅色解得 k ≤ 0.06 → 取 **0.06**（4.65:1；k=0.1 只有 4.40，不达标）。**必须按峰值而不是中位数（0.247）算**：星轨在动，同一枚文字像素的底随时间明暗波动，按中位数设计等于放任它闪烁出界。浅色比深色严 2.5 倍，因为那里压的是接近纯黑的 `text-0`。
- **实现落点**：渐变本体在 `StarTrails.vue` 的 scoped `.st-fixed`（次级页那块 `position: fixed` 画布）上，叫 `--_sky-mask`。`mask` 走 alpha 模式，故 `rgba(0,0,0,var(--sky-k))` 的 alpha 就是"天空保留多少"。选画布而不是页面容器有两个硬理由：⑴ 一块画布服务全部次级页（`isSub` = path 不等于首页），改一处即全站一致；⑵ 画布在 `main` **之外**，不会像文章页进度线那样被 `fall` 转场期间页根的 `transform` 抓去当包含块。不支持 `mask-image` 的浏览器等于回到改前状态（可读性不达标但不会画错），属优雅降级。首页那台 `.st-abs` **不进这里**——它是主视觉，压暗带等于把盘子本身压掉一半；首屏文字对比由 `.title` / `.manifesto` 自己的 `--ink-0` `text-shadow` 承担。
- **固有取舍，别当缺陷报**：视口 ≤1120px 时羽化归零，即**窄屏上一次级页的天空被整片压低**（浅色主题下几乎看不见）。手机屏没有横向余量可留给天空，这是几何事实；大气感由首页那台不加遮罩的相机和宽屏两侧的侧廊承担。若日后要在窄屏找回天空，方向是给它一条**纵向**出口（顶部条带），而不是调大 `--sky-k`——那等于把可读性换回去。
- 三者的关系收敛成一句话：**暗带管"读得清"，卡片管"是一组"，`.en-glass` 管"长时间阅读时的隔离"**。前两者不再是同一件事。

**三条关于底色的硬规矩。**

1. 凡是"跟随底色"的语义色都必须在两套主题里各自定义。`--scrim` 深色用深底色、浅色用亮底色，**不要在浅色上复用深色的 `rgba(2,2,4,…)`**——未定义会让使用处的 `var(--scrim)` 整条声明失效（首页文字底衬即由此消失过）。同理 `--shadow`：深色是近黑、浅色是底色同族的深色，拿浅色的 `--ink-2` 当阴影会晕出一圈浅色光斑（文章页阅读底板曾如此）。
2. 这类"底色 + 一个百分比"的令牌写成 `color-mix(in srgb, var(--ink-0) N%, transparent)`，不抄字面量——抄死值会在下次改 `--ink-0` 时静默落后。亮色冷色化那一批正是这么漏掉一块底板的：首页抽屉当场改成跟随 `--ink-0`，文章页 `.en-glass` 还留着旧米黄，同一件表面分叉两处，隔了一天才并回同源。
3. **唯一的例外是 `--void-a`**：`StarTrails.vue` 用 `getPropertyValue('--void-a')` 拿**原始串**直接喂 canvas 的 `fillStyle`，canvas 不解析 `color-mix()`，写进去那条填色会整条静默失效（画错但不报错）。所以它是手抄的 `--ink-0` 字节值，**改底色必须两处一起动**——这条不要"顺手统一"成 color-mix。

**为什么只有标题层自托管**：中文衬线三平台没有共同系统字体（macOS 命中 Songti SC，**Windows 会落到 SimSun**），而 `--font-display` 最大到 132px，品牌观感全压在这一层；正文用系统宋体栈既合格又不付下载代价。

**子集怎么来**：`@font-face` 声明在 `site.css`，字体与许可在 `src/assets/fonts/`，由 `npm run font:build`（`scripts/build_font.mjs`）从本机 Noto Serif SC 可变字体生成——GB2312 一级字表 3755 字 ∪ 仓库现有内容用字（当前 3922 字 ≈ 703 KB），并 `wght=700` 实例化（展示层元素全部为 700，单实例体积最小）。字表改为「仅内容用字」可压到约 174 KB，代价是新文章的标题字可能单字回退。

**两条约束**：① 产物必须提交，构建与 CI **不调用**该脚本（因此不依赖源字体）；② 该族只有 700 一个字面，新增 `--font-display` 消费方若不显式写 `font-weight: 700`，会直接以这个 700 字面渲染。

### 4.6 指针反馈词汇：两档时长、两档位移

鼠标指到会怎样，全站只有这一套词汇（令牌定义在 `site.css` §1）。收口前实测到的分散程度：时长 0.22 / 0.24 / 0.25 / 0.28 / 0.3 / 0.32 / 0.5 七个值，右移 8 / 5 / 4px 三套幅度，按钮抬起 -1 / -2px 两档——同一件事在不同页面读起来就是"不统一"。

| 令牌 | 值 | 管什么 |
| --- | --- | --- |
| `--dur-fast` | `0.22s` | 指针反馈里的**颜色与描边**（hover 变色、边框冷移、底色亮起） |
| `--dur` | `0.3s` | 指针反馈里的**位移与缩放**（标题右移、按钮抬起、照片抬起、下划线画出、透镜淡入） |
| `--nudge` | `4px` | 行内元素被指到时右移：卡内标题、曲名、动态正文、抽屉箭头、↗ 箭头的水平分量 |
| `--lift` | `-2px` | 整枚控件抬起：按钮、顶栏图标钮、后台图片格、↗ 箭头的垂直分量 |

**只有"指针反馈"归这四枚管。** 入场动画、抽屉与浮层开合、打字机光标退场、`fall` 转场、按钮的 sheen 扫光、衍射芒的缓绽（0.26s / 0.4s，它要读成"星光绽开"而不是"控件响应"）都不在这套词汇里，各自保留既定手感。

**新增一处 hover 动效时**：要么用这四枚令牌，要么把例外显式写进 `tests/motion-feedback.test.mjs` 的 `NON_FEEDBACK` 名单——那条判据会红，除非你承认它是例外。

**卡面亮不亮不分角色，透镜也不分角色。** 试过只让 `a` / `button` 的卡亮（21 张 `<div>` 卡因此静默），整站读下来发白、单薄，当日改回；接着也试过只给可点的卡挂透镜，结果同样是"同一类表面两种待遇"。现在 `.en-card` 一律 hover 亮边 + 亮底 + 跟随指针的冷色透镜，**能点与否改由两条更诚实的通道说**：`cursor`（`pointer` / `default`）与卡片本身是不是链接。
透镜的可见范围是一笔**两头只能取一头的账**：`circle 260px` + 72% 才淡出的那条长尾就是"柔和"的来源，而宿主 `overflow: hidden` 会裁掉光斑——窄卡裁得多、满宽卡整条尾巴露出来，所以同一枚透镜在不同卡上大小读起来不一样。试过收到 `200px` + `60%` 让各卡一致，当日被否（不柔和），已按原值恢复。**要一致就得牺牲长尾，别再两头来回改**。`tests/motion-feedback.test.mjs` 钉住"每张卡都带透镜"与"卡面 hover 不分角色"两条。

**"点开看大图"两处共用 `cursor: zoom-in`**（文章页插图与映像墙照片——后者原先是按钮默认的 `pointer`）。同一件事不该有两种指针。

### 6.4 基元与特异度陷阱（改样式前必读）

`site.css` 的规则分两类，**前缀规则不同，写错是静默失效**：

- **带 `html:root` 锚点的**：两套主题块、`.en-glass`（`site.css` §6c）、`.en-prose`（`site.css` §9）等需要压过基线令牌的规则。锚点给的是 (0,1,1)。
- **刻意不带前缀的**：`.en-shell` / `.en-lens` / `.en-spike` 与 §6d 的卡片基元。

陷阱在第一类的反面：给卡片基元加上 `html:root` 前缀就是 (0,2,1)，而各页 scoped 的 `.head[data-v-x]` 只有 (0,2,0)——页面想把基元扳回自己的形态（`flex-direction` / `padding` / `gap` / `min-height`）会**不报错、不红、CSS 面板里看不出，只是那一行白写**。这条陷阱一度同时压着五处死规则（首页精选的封面贴边、音乐页头卡的横排、曲目卡的 `gap: 0` 与内边距、动态卡的 `min-height: 0`、文章卡的封面贴边）。

反过来，需要"页面扳不动"的规则才加锚点：`html:root .en-prose p` 是 (0,2,2)，页面 scoped 抢不过——所以往 `.en-prose` 里塞自定义眉标之前，先把它放到 wrapper 外面，别去抢特异度。

`.en-*` 只存在于本站视图里，皮肤网关（`html[data-skin='neo']`）已随命名收口退役。

## 8. 页面要点

- **首页**：`HorizonHero.vue` 排版层浮于星轨之上，**水平居中、整块上提**。`h1.title` 是站名 `N.heroTitle`，进场逐字打出（260ms 起笔、每字 82ms），光标 `.caret` 用 `--cold`（光标属交互），**打满后再闪 1.5s 就淡出退场**——一枚永久闪烁的竖线读起来像没加载完，不像标题；减弱动效下它干脆不出现，宣言两行的 `animation-play-state` 在 `ready` 之前一直是 `paused`（暂停期间连 `animation-delay` 的钟都不走），打满才放行。中英两行要读成一个 lockup 而不是"大标题 + 小副标"：站名 `clamp(22px,4.2vw,60px)` 配 `0.18em` 字距，十六字宣言 `clamp(18px,3.0vw,38px)`（≈1.6:1，两行宽度接近：英 ≈12.6em / 中 ≈18.4em）、基线字距 `+0.08em`（负字距是英文排版的遗留，汉字粗宋会互相咬）、行高 1.9、两行间距 `--space-3`——站名是第一眼，但那十六个字才是有分量的一句。首屏文字不叠底衬，只靠 `.title`/`.manifesto` 自己的 `--ink-0` `text-shadow` 立着（§9 第 5 条）。
  首屏地景是一条**地平线横带**（`.hero-plate`，钉在底边，高度 = `--band-h: clamp(54svh, 31vw, 70svh)`）。31vw 是照片按 cover 铺满宽度时自己的高度（素材 6000×1860，ar 3.226），所以宽窗口自动把折线抬高、一寸不缺它；视口够方时退回 54%，上半屏整片留给排版。上限 70svh 是留给天空与排版的：3440×1200 那种超宽窗口到顶仍切 21.2%，再抬就把站名顶进顶栏，这一档是有意不让。`background-position: 50% 0` 把素材第 0 行永远钉在横带顶边，边界两侧同色。
  文字块不垂直居中：`.hero-text` 的底部垫量**由峰顶位置反解**——`--peak-y = 折线 + 0.208 × max(--band-h, 31vw)`（山尖取 `ridge.js` 折线的最小值 v=0.208，落在 u=0.515，正压在居中的联句底下，所以这是硬约束），`垫 = --svh + --lockup-h - 2(--peak-y - --crest-gap)`，`--crest-gap: 56px`。`--lockup-h` 由 `.title`/`.manifesto` 自己的字号/行高令牌算出（两处手打的数字没了）；垫量下限 `--space-4`、上限 0.42 个视口高，后者只防"窗口矮到装不下这条链时 padding 吃掉内容盒"。**为什么必须连着算**：横带一改自适应，固定 vh 就露馅——1920×950 上联句与山尖的间距从 +55px 变成 -13px（压上山尖）。两个旋钮都在 `.hero` 上：`--band-h` 的上限管山占多高，`--crest-gap` 管字离山尖多远。`.hero` 的高度收进 `--svh` 一枚令牌（所有算式拿它当分母，高度若与令牌分家，几何就骗人）。实测读数：2560×1392 上文字块只上移 6px（垫 210→219）而裁图 5.3%→0；1920×950 上横带 513→595px、裁图归零，代价是块心抬到视口 19% 处。
  **淡出不在 CSS 里，烘在素材里**：`build_plate_bg.ps1` 取原图 700~2560 行，在山脊（峰顶实测 1120 行，读自 25px 网格渲染）以上盖一层竖向天空纱，顶端正好落在 `--ink-0`、到峰顶收敛为 0，所以山一寸没被遮。实测边界差 1/765 通道和，淡出跨 220px，进入段每 20px 降 0.021 亮度。暗色 `--hero-img` 是**同一取景的压暗版**（`plate-hero-deep.jpg`）：同一个 `$full`、同一裁剪、同一条天空纱，只把纱色换成压向 `#020204`（调色为 `$HERO_DEEP = $HERO × K`，`K=0.32`，3×3 与 RGB 偏移**一起**缩，纯黑才落回 `#020204` 而不是偏移留下的 `#030810`；`DEEP_HERO_K` 可覆盖），保留 `$HERO` 的色相让山脊可读，实测素材第 0 行就是 `#020204`、边界台阶降到 ≈0.3 ΔL\*；两套主题因此共用 `ridge.js` 那一条折线。首屏视差随滚动以 0.25 倍速下沉并淡出。
- **首页折线以下**：风景底片是挂在 `App.vue` 上的 `.sub-plate`（`position: fixed` 铺满视口）。素材由 `npm run bg:build` 从 `plates-src/` 的原图烘出来，原图不进仓库。**底片是清晰的**：糊不糊是运行时参数 `--plate-blur`（0–12px 滑杆，**初值 12 = 拉满**，见「设置卡」条），素材一律出清晰版，所以滑杆两端都有实义，0 那一档是真清晰。五张轮播**每张 10s**：`--plate-cycle: 50s`，父层那张 + 四个 `.sub-plate > i` 共用**一条** `plate-slot` 关键帧、只靠 `animation-delay`（9/19/29/39s）错开——每张独占 9s、两端各 1s 与邻张交叉，延迟取"10s 的倍数减 1s"正是为了让一张的淡出与下一张的淡入落在同一秒上。加一张要动三处（模板多一个 `<i>`、多一档延迟、周期 +10s），且关键帧的 2%/20%/22% 是按 50s 一圈算的，改了周期就得重算。减弱动效下停成单张不轮播。**每一档自带一份压暗渐变**（`transparent 18% → var(--ink-0) 78%`）：渐变若只在父层写一次，浮上来的那张会盖掉压暗，文字对比当场没了。图层向四周多撑 3 倍模糊半径，免得边缘淡进透明露出一圈白边。

## 9. 已否掉的路（别再试，每条都带量出来的数）

这一节只收**结论是否定的**那些：它们花过实测成本，写在这里是为了不让人再量一遍。

1. **给卡片加遮罩来救可读性**——压回可读所需的遮罩 alpha 解出来是 81~85%，那时卡片等于不透明、天空白画，核心装置在列表页名存实亡（§3.3）。
2. **在风景照片上放裸字并靠渐变救**——竖向单条、上下双纱、顶部淡入三种形状都试过，最坏点卡在 1.0–1.8:1 上不去，**与渐变形状无关**（§8「首页折线以下」）。
3. **把 `--plate-blur` 烘进素材**——糊不糊是运行时参数，素材一律出清晰版，否则滑杆两端没有实义。
4. **`mask-image` 做首屏淡出**——105px 内把照片落在边上的 `#9FB4CB` 插到页面色 `#F2F5F9`，两端颜色不等，那条横杠就是这么来的；这是颜色问题不是长度问题，拉长渐变只是摊开同一段色差。同处那层 45% 的 `--scrim` 白纱也删了：它把山脚从 `#334974` 抬到约 `rgb(118,133,163)`、与照片自己的天空同亮度，山没有落点，那是「上下割裂」的另一半——`--scrim` 由此零消费方（两套主题仍各自定义着，退役要两处一起删）。
5. **暗色首屏复用抽屉那张夜景底**——切主题换了一座山（亮色雪山 / 暗色海边），且顶边只是"几乎"对齐：旧记的 1.07:1 在重烘后漂到 1.17:1（ΔL\*≈7.7），没有渐变的硬边被眼睛读成一道横杠。
6. **靠调小 `fd` 拉长尾迹**——8 位底片上 `α·fd < 0.5 LSB` 的那一档永远掉不下去，地板高度 = `0.5/(255·fd)`：旧值 `FADE_1=0.0038` 时 `round(fd·255)=1` → 地板 α≈0.5，每颗星 150s 扫过的一整圈永久留在底片上（实测残留覆盖 6.7% 像素、10 条半径行的角度覆盖率 >55%、最强一圈 100%、浅色上 Δ灰 32 的实线同心环，内圈环间距只有 9.6px 全糊成唱片纹）。**越收越浓就是这么来的**（往下调衰减 = 往上抬地板）。修法是把沉积与衰减同时 ×20（`DEP 0.0084→0.168`、`FADE_0 0.0086→0.172`、`FADE_1 0.0052→0.104`）：稳态亮度 `al/(al+fd)` 逐位不变，地板按 1/fd 掉到 Δ灰 1.6（最深档 2.5），残留覆盖 6.72%→**0.00%**、整环行 10→**0**、盖上镜头空转 10s 后均值 α 0.0109→**0.0009**。阴性对照：同样常数换 `Float32` 底片 → 残留 Δ灰 0.0，与 8 位那一臂差一个半数量级，说明差异确实来自取整。半档（×10）实测 Δ灰 3.2 也过得了判据，选 ×20 是给 1× 大屏的抗锯齿边缘留余量。**代价**：尾迹长度不能再挂在衰减窗口上（1/fd 从 83 帧掉到 4 帧，指数尾只剩 0.17°），改由弧长承载。
7. **每笔沉积不乘帧时长**——刷新率越高同一点叠得越多：120Hz 最深档实测 α=1 的实心像素 0.76%→1.89%、环间黑隙 27px→20px，而 60Hz 开发机上看不见，于是"收了参数没见轻"。`accPass(…, dep, step)` 把 `step` 也乘进沉积，60Hz 下 `step=1`，观感逐位不变，此后每个口味常量在任何刷新率上都落得准。
8. **一套星数服务两个主题**——同一个 α=0.037 压在浅色干版（底 245、墨 40，跨度 205 级）上是 7.6 级 = 3% 对比、隐进纸纹，加在近黑底（背景 2.2 级）上是 **320% 对比**，一眼读成"一片脏灰的轨迹"。深色那层灰**不是残留而是每条线自己的抗锯齿翼**：最暗活尾迹核心稳态 α = `DEP·z_min/FADE_0 = 0.168·0.16/0.172 = 0.135`（≈26 级），它的翼在中位线宽 0.96 CSS px 上取到 α≈0.037 → ≈8.2 级，与截图实测 7.0 级同数量级、同一位置。所以星数必须分档（`N_DEEP_K=0.65`：深色 182 / 浅色 280），页顶档齿/100px 1.63→**0.92**、黑隙中位 51px→**107px**、可见亮线覆盖 1.87%→**1.21%**、翼层面积 0.78%→**0.48%**；最深档深色 1.84 齿、黑隙 34px，仍低于浅色最深档的 2.55——收完不会比浅色更空。**这一维上 `fade` 是封死的**：残留/核心之比 = `0.00196/(dep·z)`，与 `fd` 无关（分子是 1 LSB 的地板 α，分母是稳态 α，`fd` 约掉了），加衰减擦不掉翼、减衰减又把地板抬回来；能动的只有同时在屏的线条数。
9. **靠超采样修"细碎"**——1× 缩放的屏上眼睛的采样网格恒为 1 CSS px：中位线宽 0.93 时脊的谷/峰 = 0.33（同一条线自己亮 30 级、暗 10 级交替），底片内部栅格换成 1.645 是 0.34、换成 2 是 0.24，**几乎没有收益**；只有把线本身加粗才动它（1.2px→0.42、1.5px→0.52、1.8px→0.63）。顺带查出 `MIN_DPR=1.8` 在 2546×1307 上被 9MP 预算悄悄夹成 1.645——那句"下限 1.8"从来没成立过。现在 `MIN_DPR`/`MAXPX` 看是纯代价（1× 屏多花 2.7× 像素换 0.01 的起伏改善），候选退回 `dpr = devicePixelRatio` + 4.6MP，但那会同时改变弧线几何平滑度与帧率，等 fps 读数再动。
10. **加粗但不减 α**——单位弧长的墨 = α·lw，canvas 的 `lineWidth` 不摊薄 alpha，加粗 1.55 倍就是把墨加 1.55 倍，等于把刚压下去的脏灰整个还回去。所以 `LW_BASE/LW_SPAN` 与 `DEP` 是一对联动常量（等墨：中位宽 0.94→1.45 CSS px 时 `DEP 0.168→0.108`）。等墨之后深色页顶齿/100px 0.92→0.92、黑隙 105/10 不动，**翼层 0.65%→0.51%（降 22%）**。同理**任何复刻这条管线的脚本都不许把落笔按周长归一**（`(1−d²/r²)²/norm` 只在 lw≈1 时恰好等价，且会把"加粗有用"从模型里抹掉），必须写成 `像素 α = 笔画 α × 与笔带的面积重叠`。
11. **`SETTLE` 那道按角度统一削沉积的暗楔**——窗口缩到 4 帧之后闭合环根本不可能形成，留下的只有全天在同一角度缺角（72° 暗楔），两条常量连同只服务它的 `smooth01` 一起删。随机抽 1–3 根独立渐隐（`FEAT`）保留——它是随机的，不是全天一刀切。
12. **把 `fall` 换成"只动 opacity/transform + 独立红移覆盖层"**——可行，但叠影模糊正是"坍缩"的手感来源，按取舍保留原样。真要回收：那是全站最贵的一处绘制（整页子树逐帧重栅格化，两页并行时更甚）。
13. **首屏放点击入口**——变星（文章节点）装置整体撤除：骑在轨迹上的星读成贴在光弧上的脏点，hover 缓绽与点击坠入自上线以来没有任何使用侧反馈。首屏从此没有点击入口，文章入口收敛到折线以下的抽屉精选卡。
14. **在次级页也画山**——沉积时切弧会让次级页（背景无山）在同一张底片上读出一圈缺角，所以遮挡只能在绘制时按相机裁（§3.1）。
15. **自造的项目介绍浮层**（Teleport + 78% 糊底 + 55% 玻璃板 + ✕ 浮在屏幕角 + 框底按键提示）——借的是看照片的皮：浅色主题 `--ink-0` 是近白 `#f2f5f9`，78% 的"暗化"成了一片奶白雾，板子用的又是同一支 `--panel-bg`（ink-0 55%），**两者同色、边读不出来**（深色下不显，因为那时 ink-0 真是黑的）；而它是站内第八种"点开看看"的容器（文章页 / 映像灯箱 / 插图灯箱 / 曲目表折叠 / 播放器卡 / 设置卡 / 抽屉）。并成文章那一类之后，容器少一个、返回机制也少一套。它当时还留了一条：面板自己是 `overflow-y: auto` 的内滚容器，被 `site.css` 那条不限容器的 `::-webkit-scrollbar-thumb` 套上**第二条朱砂滚动条**，正贴在卡的右边缘。
16. **用 `router.back()` 实现详情页返回**——深链接直接落在详情页时 `history.state.back` 不为 null，实测按 Esc 退回的是首页而不是列表（§8）。
17. **`<button>` 里放 `<h3>`/`<p>`**——按钮不是透明内容模型，非法；卡面一旦从 `<a>` 换成 `<button>`，标题与段落要改成 `<span>`（`<a>` 里则可以）。
18. **把 `--void-a` 统一成 `color-mix()`**——canvas 不解析它，写进去那条填色整条静默失效（§4.2 第 3 条）。
19. **两条仍然成立的工程结论，从已删功能里留下**：① 下沉用 `translate`、居中用 `transform`，两者是可叠加的独立属性——当年带前缀的 `.glyph`(0,2,1) 压过 scoped 的 `translate(-50%,-50%)`(0,2,0)，让 620px 首页大字横跳约 270px；凡以后再有"随 `--shift` 下沉的装饰层"，直接踩这条。② 「本次停留」计时读数不该存在——它数的是打开页面后的秒数、没有信息量，还会把 `sky.t0` 的全站曝光时钟错标成"自这一页打开时起算"。
20. **在卸载里复位 `document.title`**——`router.afterEach` 与新页挂载都排在卸载之后，那句兜底会把「文章 · Escaping Notes」覆成站名（§6.3）。
21. **两条不再引入的管线**：已删除的 `BlackHole.vue`（黑洞 / 吸积盘 / 仪表环）与已删除的 `DepthRail.vue`（红移坠入深度轨；深度改由 `App.vue` 写 `--shift`）。
